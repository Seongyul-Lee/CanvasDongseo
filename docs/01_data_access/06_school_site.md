| 항목 | 내용 |

> **이 문서의 역할**: 학교 홈페이지 CMS로 학교 공지와 학과·기관 공지를 읽는 경로를 정의한다. Component `school_site`.

## 1. 공통: 학교 홈페이지 CMS (2026-11-08 확인)

학교 공지와 학과 공지는 **같은 CMS**를 쓴다. 로그인 없이 읽을 수 있다. 응답은 HTML이며, 공지용 RSS·JSON은 찾지 못했다.

| 요소 | 형식 |
|---|---|
| 게시판 목록 | `{사이트}/index.php?pCode={게시판 코드}` |
| 페이지 | `&pg={n}` (1부터) |
| 상세 | `&mode=view&idx={글 번호}` |
| 첨부파일 | `&mode=fdn&idx={글 번호}&num={첨부 순번}` |
| 분류 | `&CgCode={분류 코드}` (분류를 쓰는 게시판만. 빈 값 = 전체) |
| 검색 | `&sf={검색 대상}&skey={검색어}&st=and` (GET 폼. 아래 표) |

**검색 매개변수** (2026-11-08, 학교 학사 게시판에서 결과 건수로 확인)

| 매개변수 | 값 | 확인한 동작 |
|---|---|---|
| `sf` | `b_subject`(제목), `b_content`(내용), `b_subject\|b_content`(제목+내용), `reg_name`(작성자) | `b_content`와 `b_subject\|b_content`의 결과가 같았다(제목도 내용 검색에 포함되는 것으로 보임) |
| `skey` | 검색어 | **띄어쓴 단어는 OR로 검색된다.** "수강" 198건, "신청" 246건, "수강 신청" 409건, "수강신청"(붙여 씀) 34건 |
| `st` | `and`(폼 기본값), `or` | 결과에 영향이 없었다. 폼 기본값 `and`를 그대로 보낸다 |
| `CgCode` | 분류 코드 | 검색·페이지와 함께 쓸 수 있다(`CgCode` + `sf`·`skey` + `pg` 조합 확인) |

- 여러 단어를 모두 포함하는 글이 필요하면 단어 하나로 검색한 뒤 나머지 조건은 앱에서 거른다.
- 총 건수: 일반 글의 번호가 내림차순이므로 첫 일반 글의 번호가 결과 총 건수다(학사 게시판 전체 833건).

**고정 공지**: `tr.isnotice` 행(번호 대신 공지 아이콘)은 **모든 페이지와 모든 검색 결과의 맨 위에 반복된다.** 검색어와 맞지 않아도 나온다. 일반 글은 `tr.child_1`·`tr.child_2` 행이고 한 페이지에 15개다. DS는 고정 공지를 따로 표시하고, 같은 `idx`를 중복으로 세지 않는다.

**목록 HTML** — 열 구성은 게시판마다 다르지만(분류·작성자·파일 열이 있거나 없음) 셀의 CSS 클래스는 같다. 열 순서가 아니라 클래스로 읽는다.

| 클래스 | 내용 |
|---|---|
| `td.f-num.num` | 번호(고정 공지는 번호 대신 표시가 올 수 있음) |
| `td.f-cate.cate` | 분류(있을 때) |
| `td.f-tit.subject` | 제목, 상세 링크(`mode=view&idx=`) |
| `td.f-nm.writer` | 작성자(있을 때) |
| `td.f-date.date` | 등록일 |
| `td.f-hits.read` | 조회수 |

**상세 HTML** — `.board-view-title`(분류·제목·조회), `.board-view-winfo`(작성 정보), `ul.board-view-filelist`(첨부: 파일 이름·크기·`mode=fdn` 링크), 본문 영역.

- robots.txt는 `/_Admin`, `/_Data`, `/_Inc` 등 내부 경로만 막고 게시판 페이지(`index.php`)는 막지 않는다.
- 요청 간격을 두고(출처당 동시 1개), 이미 받은 글(`idx`)은 다시 받지 않는다.
- Component: `school_site` 하나에 공통 CMS 파서(목록·상세·첨부)를 두고, 학교 공지와 학과 공지 DS가 같은 파서를 쓴다.

## 3. 학과 공지

**사이트 주소 패턴**: 학과·학부·단과대학 사이트는 대부분 `https://uni.dongseo.ac.kr/{사이트 코드}/`에 있다. 홈페이지(`www.dongseo.ac.kr/kr/`)의 링크에서 사이트 코드 목록을 얻을 수 있다(예: `computer` 컴퓨터공학부, `sw` 소프트웨어전공, `nursing` 간호학과, `business` 경영학부, `game` 게임학과).

- 단과대학(`software`, `design`, `mc` 등), 학부(`computer`), 전공(`computereng`, `sw`)이 각각 사이트를 가진다. 학생은 여러 단계의 공지를 봐야 할 수 있다.
- 대학원·미래커리어대학은 한 사이트 안의 `pCode`로 학과를 나눈다(예: `graduategeneral/index.php?pCode=MN8000045`).
- 일부 사이트는 다른 하위 도메인에 있다(예: `stellararts.dongseo.ac.kr`). 확인 필요.

**공지 게시판 코드는 학과마다 다르다** (8곳 확인):

| 사이트 | 메뉴 이름 | 게시판 코드(`pCode`) |
|---|---|---|
| `computer` | 공지사항 | `notice` |
| `sw` | 공지사항 | `MN1000013` |
| `nursing` | 학과 공지(학사) / 프로그램 공지(인증) / 실습 공지(임상실습) | `notice` / `prognotice` / `trnotice` |
| `business` | 공지 | `news` |
| `game` | 학과소식(첫 화면에는 "공지사항") | `MN5000017` |
| `police` | 공지사항 | `notice` |
| `designcollege` | 공지사항 (메뉴에 두 개) | `MN0000326`, `notify` |
| `english` | 학과소식(첫 화면에는 "학과공지") | `notice` |

- 학과마다 공지 게시판이 하나가 아닐 수 있고, 메뉴 이름도 제각각이다. 코드를 하나로 가정하지 않는다.
- **학과 → 사이트 코드·게시판 코드 목록(레지스트리)** 을 데이터로 둔다. 코드에 박지 않는다.
- 레지스트리를 만드는 방법: 각 사이트 첫 화면의 메뉴에서 이름에 "공지"·"소식"이 들어간 `index.php?pCode=…` 링크를 후보로 뽑고, 그 페이지가 게시판 목록 형식(§1)인지 확인한다. 자동으로 찾은 결과는 사람이 확인한 뒤 레지스트리에 넣는다.
- 학생의 학과는 Canvas 프로필로는 알 수 없다. 사용자가 고르게 하거나 학생지원시스템([07_student_portal](07_student_portal.md))에서 얻는다.
- **전체 사이트의 게시판 코드는 [부록 A](#부록-a-학과기관-사이트-공지-게시판-목록)에 있다.** 75곳 중 공지 게시판을 찾지 못한 곳은 4곳(`ace`, `chi`, `eng`, `micro`)이다.
- 부록 A에서 확인한 차이:
  - 공지 게시판 코드의 절반가량이 `notice`이고, 나머지는 `MN…` 숫자 코드나 `news`, `notice_01`, `01_notice`, `fashion_notice`, `schedule` 같은 고유 코드다.
  - 공지 게시판이 여러 개인 학과가 많다(간호학과 3개, 호텔경영학과 3개, 회계세무학전공 2개 등). 취업·실습·공모전 공지가 따로 있다.
  - 같은 `notice`라도 목록 형식이 다른 곳이 있다(임상병리학과 `notice`는 표 형식이 아니고 `generalboa`가 공지 게시판).
