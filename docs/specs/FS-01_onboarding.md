# FS-01 온보딩

| 항목 | 내용 |
|---|---|
| 독자 | 개발자 본인, 후속 문서·구현을 돕는 AI 에이전트 |
| 상태 | 초안 |

| 화면 | 온보딩(단계 진행 바, 단계별 카드) ([UX Strategy §7.2](../06_ux_strategy.md#72-mvp-화면)) |
| 유스케이스 | 이 FS에 따로 없다. 각 단계는 [FS-02](FS-02_ai_connection.md)(AI 설치 감지·로그인), [FS-03](FS-03_school_account.md)(`LoginWithOtp`, `GetAuthState`), [FS-05](FS-05_departments.md)(`ListDepartments`, `SetDepartments`)의 유스케이스를 쓴다 |

> **이 문서의 역할**: 앱을 처음 쓰는 학생이 AI 연결 → 학교 계정 연결 → 학과 선택을 거쳐 대화에 이르는 **순서, 건너뛰기, 중간에 끊겼을 때 재개**를 정한다.
> 각 단계 안의 동작(설치·로그인·OTP·학과 목록)은 FS-02, FS-03, FS-05가 정하고, 단계 카드의 상태 표시는 [FS-06](FS-06_connection_status.md)의 판정 결과를 쓴다.

## 1. 범위

| 하는 것 | 하지 않는 것 |
|---|---|
| 세 단계의 순서와 단계 사이 이동 | 각 단계 안의 입력·판정·오류 처리(FS-02, FS-03, FS-05) |
| 단계별 건너뛰기 허용 여부 | 단계 카드의 상태 종류·점·버튼 판정(FS-06) |
| 온보딩을 끝내는 조건 | 학생지원시스템 로그인([UX Strategy §7.2](../06_ux_strategy.md#72-mvp-화면): 온보딩에 넣지 않는다. FS-04) |
| 앱을 껐다 켜는 등 중간에 끊겼을 때 재개 | 학과를 학생지원시스템 정보로 미리 채우기([06_school_site §3](../layers/data_access/06_school_site.md#3-학과-공지)) |
| 온보딩을 마친 뒤 대화 화면으로 넘기기 | 온보딩 뒤 연결이 끊겼을 때의 회복(연결 알약과 설정, FS-06) |

## 2. 기능 요구사항

### F1 단계와 순서

| 순서 | 단계 | 동작을 정하는 FS | 끝난 것으로 보는 조건 |
|---|---|---|---|
| 1 | AI 연결 | FS-02 | AI가 최소 버전 이상으로 설치돼 있고, 로그인돼 있고, 플랜이 Claude Code를 쓸 수 있다 |
| 2 | 학교 계정 연결 | FS-03 | `GetAuthState`가 연결됨(또는 곧 만료)을 돌려준다 |
| 3 | 학과 선택 | FS-05 | 설정에 학과가 1~2개 저장돼 있다 |

- 순서는 [UX Strategy §7.2](../06_ux_strategy.md#72-mvp-화면)를 따른다. 진행 바는 세 단계를 모두 보이고, 지금 단계를 강조한다.
- 각 단계가 끝났는지는 **온보딩이 따로 기록하지 않고** 각 FS의 상태 조회 결과로 판정한다. 온보딩 카드, 설정 행, 연결 알약이 같은 판정 결과를 쓴다는 원칙([UX Strategy §7.5](../06_ux_strategy.md#75-설정))을 지키기 위해서다(추론, §6).
- 단계가 끝나면 다음 단계로 자동으로 넘어간다. 앞 단계로 돌아가는 버튼을 둔다(추론, §6). 돌아가도 끝난 단계는 끝난 상태로 보인다.

### F2 이미 끝난 단계 (S1-3)

- 온보딩을 열 때와 각 단계에 들어갈 때 해당 FS의 상태를 먼저 조회한다. 이미 끝난 단계는 입력을 받지 않고 끝난 카드로 보인 뒤 다음 단계로 넘어간다.
- 터미널에서 이미 Claude Code에 로그인한 학생은 AI 단계에서 설치·로그인 화면을 보지 않는다(S1-3, [ai_adapters §2](../layers/05_ai_adapters.md#2-claude-로그인) "계정 폴더").
- 상태 조회가 끝나기 전에는 카드가 "확인 중"이다(FS-06). 확인 중인 단계에서 입력을 받지 않는다.

### F3 건너뛰기

| 단계 | 건너뛰기 | 건너뛰었을 때 |
|---|---|---|
| AI 연결 | "나중에 하기"로 넘어갈 수 있다(추론, §6) | 대화를 보내면 AI 연결 안내가 앱 메시지로 나온다([FS-07](FS-07_conversation.md), FS-02). 연결 알약에 AI 행이 문제 상태로 잡힌다(FS-06) |
| 학교 계정 연결 | "나중에 하기"로 넘어갈 수 있다(추론, §6) | 학교 데이터 질문에 연결 안내가 나온다. 로그아웃 상태와 같다([FS-03 F6](FS-03_school_account.md#f6-로그아웃)) |
| 학과 선택 | **건너뛸 수 없다**(S1-7) | — |

- 학과 선택 단계에는 "나중에 하기"와 "완료"를 누를 수 있는 다른 길이 없다. 학과를 1개 이상 고르기 전에는 완료 버튼이 비활성이다.
- Free 플랜이라 로그인이 끝나지 않는 학생([FS-02 F4](FS-02_ai_connection.md#f4-플랜-판정-s1-2)), `AiUnavailable(PlanNotSupported)`로 판정된 학생, 설치를 거절한 학생(`Rejected(UserDeclined)`), 업데이트가 필요하거나 설치·업데이트가 실패한 학생([FS-02 F2](FS-02_ai_connection.md#f2-설치와-업데이트-s1-1))도 AI 단계를 "나중에 하기"로 넘겨 학교 계정과 학과 단계를 마칠 수 있다(추론, §6).
- 건너뛴 사실은 따로 저장하지 않는다. F5에 따라 온보딩이 끝나기 전에 다시 열면 건너뛴 단계를 다시 보인다.

### F4 온보딩 끝내기

- 학과 선택 단계에서 학과를 저장하면(FS-05) 온보딩이 끝난다. 학과는 마지막 단계이고 건너뛸 수 없으므로, **설정에 학과가 있으면 온보딩을 마친 것으로 본다**(추론, §6).
- 끝나면 대화 화면의 새 대화로 간다. AI 단계를 마쳤다면 바로 질문을 보낼 수 있다(S1-1 "대화창에 첫 응답").
- 온보딩을 마친 뒤에는 앱을 다시 시작해도 온보딩을 보이지 않는다. 그 뒤 AI·학교 로그아웃이나 연결 끊김은 연결 알약과 설정 > 연결이 다룬다(FS-06). 온보딩으로 되돌리지 않는다.

### F5 중간에 끊겼을 때 재개

- 온보딩이 끝나기 전에 앱이 꺼지면, 다음 시작 때 온보딩을 다시 연다. F2에 따라 끝난 단계를 건너뛰고 **끝나지 않은 첫 단계**에서 시작한다.
- 단계 안에서 진행 중이던 일은 이어 가지 않고, 해당 FS가 정한 처음 상태로 돌아간다.

| 끊긴 곳 | 다음 시작 때 |
|---|---|
| AI 설치 중 | 설치 감지(FS-02)부터 다시 한다. 반쯤 설치돼 감지되지 않으면 설치 동의부터 다시 묻는다 |
| AI 로그인 대기 중 | 앱이 꺼지면 로그인 프로세스도 끝난다([System Architecture §2](../02_system_architecture.md#2-프로세스-구조)). 다시 시작할 때 계정 상태를 조회해, 브라우저에서 로그인이 끝났으면 끝난 단계로 본다 |
| 학교 계정 OTP 입력 중 | 연결이 끝나지 않았으므로 학번·비밀번호 입력부터 다시 한다([FS-03 F1](FS-03_school_account.md#f1-처음-연결)) |
| 학과를 고르는 중 | 저장하기 전 선택은 남지 않는다. 목록부터 다시 고른다 |

- 재개를 위해 온보딩 진행 상태를 따로 저장하지 않는다. 비밀(학번·비밀번호·OTP)을 온보딩이 들고 있지 않는다.

## 3. 예외

각 단계 안의 예외는 해당 FS의 §3이 정한다. 온보딩은 아래만 다룬다.

| AI 단계의 상태 조회가 오래 걸림(키체인 허용 창 등) | 시작 구간 시간 초과 | — | FS-02의 "항상 허용" 안내. 학생은 "나중에 하기"로 넘어갈 수 있다 |

| AI 설치·업데이트가 실패함 | — | `Temporary` | 다시 시도(설치·업데이트 버튼). "나중에 하기"로 넘어갈 수 있다 |

| 쓸 수 없는 계정으로 판정됨 | — | `AiUnavailable(PlanNotSupported)` | 유료 플랜 안내(FS-02). "나중에 하기"로 넘어갈 수 있다 |
| 학교 연결 중 네트워크 오류 | — | `Temporary` | 다시 시도. "나중에 하기"로 넘어갈 수 있다 |
| 학과 목록을 만들 수 없음 | — | FS-05가 정한다 | FS-05가 정한다. 학과 단계는 건너뛸 수 없으므로 온보딩은 끝나지 않는다(§6) |
| 학과를 고르지 않고 끝내려 함 | — | — | 완료 버튼이 비활성이다 |

## 5. User Flow (UF-01)

이 기능의 [Design Process ①](../03_design_process.md)에서 그린다. 그릴 갈래: 처음부터 끝까지(세 단계 순서), 이미 끝난 단계 자동 통과(S1-3), AI·학교 단계 건너뛰기, 학과 단계 건너뛰기 불가, 중간에 끊긴 뒤 재개(F5 표의 네 곳). 각 단계 안의 갈래는 UF-02, UF-03, UF-05에 두고 여기서는 링크만 한다.

## 6. 미확인 항목

- **앞 단계로 돌아가는 버튼**: F1에 넣었지만 [UX Strategy §7.2](../06_ux_strategy.md#72-mvp-화면)의 온보딩 행(T3 Code `WelcomeWizard`의 단계 진행 바, 카드 상태)과 시나리오에는 근거가 없다. T3 Code `WelcomeWizard`에 이 버튼이 있는지 확인하고, 없으면 뺀다
- **AI·학교 단계 건너뛰기 허용(F3)은 추론이다.** UX Strategy는 학과 선택만 "건너뛸 수 없다"고 정하고(S1-7), 다른 두 단계의 건너뛰기는 정하지 않았다. 허용 근거: 로그아웃 상태의 대화 안내가 이미 FS-02·FS-03에 있어 새 상태가 생기지 않고, Free 플랜 학생(S1-2)이 온보딩에 갇히지 않는다. 막는 안도 있다(AI 없이는 대화가 안 되므로 AI 단계만 필수). 확인 방법: 사용자 결정
- **온보딩 진행 판정을 어디에 두는지가 아키텍처에 없음 → UX Strategy §12 후보.** [presentation §1](../layers/03_presentation.md#1-개요)의 `presenters/shell`은 연결 상태 모음과 대화별 상태만 판정한다. "지금 어느 단계인가, 온보딩이 끝났는가"는 AI(`usecases/ai`)·학교(`usecases/school`)·학과(`usecases/school`) 출력 DTO를 함께 보므로 `shell`에 두는 것이 자연스럽다(추론). `shell`의 판정 목록에 더할지 정한다
- **온보딩 완료를 "학과가 저장돼 있음"으로 판정(F4)은 추론이다.** 따로 완료 표시를 저장하지 않기 위한 것이다. 학과 설정이 지워지는 경로가 생기면(MVP에는 없다) 온보딩이 다시 열린다. 별도 완료 값을 `SettingsRepository`에 둘지 정한다. 둔다면 아키텍처에 없음 → UX Strategy §12 후보
- 저장된 학과를 읽는 유스케이스가 [application §3](../layers/02_application.md#3-유스케이스-후보)에 없다(`ListDepartments`는 선택 목록, `SetDepartments`는 쓰기). F4 판정과 설정 > 학과 화면 모두 필요하므로 FS-05에서 정한다
- S1-3의 성공 상태 "AI 로그인 단계 없이 **대화창이 열리고**"는 온보딩 없이 바로 대화로 가는 것으로 읽힐 수 있다. 그러나 S1-7은 "첫 온보딩에서 학과를 정한다", "학과를 고르지 않으면 온보딩이 끝나지 않고"라고 한다. 이 문서는 S1-3을 "AI 단계만 자동 통과"로 읽었다(F2). S1-3의 성공 상태 문장을 고칠지 확인한다
- 학과 목록을 만들 수 없을 때(레지스트리 오류 등) 온보딩이 끝나지 못한다. 학과 단계는 건너뛸 수 없으므로 학생이 앱을 쓸 수 없게 된다. 목록은 앱에 포함된 레지스트리에서 만드는 것으로 보이나(추론) FS-05에서 확인한다
- 온보딩 단계별 카드의 상태 종류(확인 중, 설치 안 됨, 업데이트 필요, 로그인 필요, 사용할 수 없음, 연결됨)를 학과 단계에도 쓰는지. 학과는 연결 행이 아니므로 FS-06의 판정 밖이다. Design Process ②에서 정한다
