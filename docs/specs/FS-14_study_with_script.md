> **이 문서의 역할**: FS-13으로 만들어 둔 스크립트를 근거로 대화에서 요약·퀴즈·예상 시험지를 얻는 기능의 동작과 수용 기준을 정한다. 핵심은 AI가 어떤 스크립트를 썼는지 보이게 하고, 앱 밖에서 바뀐 스크립트를 `Peer`로 다루는 것이다.
> 스크립트를 만드는 일은 [FS-13](FS-13_slide_pdf_and_script_jobs.md), `Peer` 격리 요약과 시점 경고의 공통 동작은 [FS-09](FS-09_notices_and_peer_safety.md), 대화 자체는 [FS-07](FS-07_conversation.md)이 맡는다.

## 1. 범위

| 하는 것 | 하지 않는 것 |
|---|---|
| 차시(학기·과목·주차·차시)로 스크립트를 찾아 AI에게 넘기기 | 스크립트 만들기(FS-13) |
| 스크립트의 신뢰 등급을 무결성 기록으로 정하고, `Peer`면 원문 대신 격리 요약을 넘기기 | 요약·퀴즈·예상 시험지를 코어가 직접 만들기(F3, 판단 근거는 §6) |
| 대화 AI가 요약·퀴즈·예상 시험지를 만들고, 어떤 스크립트를 썼는지 밝히기 | 만든 요약·퀴즈를 앱이 파일로 저장하기(아키텍처에 없음, §6) |
| | 퀴즈 채점·학습 기록 관리 |
| | 학교의 퀴즈 제출 등 학사에 영향을 주는 일([PRD §9.1](../01_prd.md#91-비목표-non-goals)) |
| | 기능별 전용 화면(학습 자료 화면은 MVP 이후, [UX Strategy §7.3](../06_ux_strategy.md#73-mvp-이후-화면)) |

## 2. 기능 요구사항

### F1 스크립트 찾기

- **입력**: 학생의 질문("3주차 요약해 줘"). 대화 AI가 과목·주차·차시를 정해 `cdx`로 스크립트를 조회한다(추론: 조회 명령은 아키텍처에 이름이 없다, §6). 과목이 질문에 없으면 AI가 과목 조회로 정하거나 학생에게 묻는다.
- **동작**: [domain §4.2](../layers/01_domain.md#42-학습-결과물-이름-규칙)의 키(학기, 과목, 종류 = 스크립트, `{NN}주차_{M}차시_{제목}`)로 `LearningOutputRepository`에서 찾는다. 한 주차에 차시가 여럿이면 모두 돌려준다(추론).
- 파일 경로 인자를 받는 경우 학습 자료 폴더 아래만 받는다([entrypoints §4](../layers/04_entrypoints.md#4-cdx-명령)).
- **출력**: 차시마다 키(과목, 주차, 차시, 제목), 신뢰 등급, 내용(F2). 해당 스크립트가 없으면 없다는 결과를 돌려준다.
- 스크립트가 없으면 AI는 지어내지 않고 없다고 말하며([UX Strategy §9](../06_ux_strategy.md#9-ai-응답-경험-원칙) R2), FS-13으로 만들 수 있다고 안내한다. 동영상이 받아져 있지 않으면 FS-12부터다.

### F2 신뢰 등급과 넘기는 내용

- `LearningOutputRepository`는 조회 때 기록의 HMAC과 파일 해시가 맞는지 확인하고 등급을 함께 돌려준다([application §4.3](../layers/02_application.md#43-학습)).

| 확인 결과 | 등급 | AI에게 넘기는 내용 |
|---|---|---|
| HMAC 맞음, 해시 맞음 | `Official` | 스크립트 원문(`[mm:ss] 문장` 줄) |
| 해시 다름(앱 밖에서 파일이 바뀜) | `Peer` | 원문 대신 격리 요약 |
| HMAC 다름(파일과 기록을 함께 바꿈) | `Peer` | 원문 대신 격리 요약 |
| 기록 없음(앱이 만들지 않은 파일) | `Peer` | 원문 대신 격리 요약 |

- `Peer`면 AI용 Presenter가 원문 대신 도구 없는 격리 세션의 요약을 넣고([entrypoints §5](../layers/04_entrypoints.md#5-ai용-presenter), [ai_adapters §5](../layers/05_ai_adapters.md#5-hook-설정과-격리-요약)), `cdx hook post`가 그 대화를 "`Peer` 읽음"으로 기록하고 경고를 넣는다. 그 대화의 첫 위험 도구 호출은 한 번 거부된다([security §4.2](../cross_cutting/01_security.md#42-장치)). 이 동작은 FS-09의 공통 동작과 같다.
- 결과 JSON의 항목마다 등급을 붙인다. 등급은 내용을 해석하지 않고 기록 확인 결과로만 정한다([security §4.1](../cross_cutting/01_security.md#41-신뢰-등급)).

### F3 요약·퀴즈·예상 시험지

- **대화 AI가 만든다.** 코어는 스크립트를 찾아 넘기는 데까지 하고, 요약·퀴즈·예상 시험지의 내용을 만들거나 형식을 정하지 않는다(판단 근거는 §6).
- 결과는 대화의 AI 메시지로 나온다(S7-3, P1). 앱 메시지가 아니다.
- 여러 차시(예: "중간고사 범위 예상 시험지")를 쓰면 F1을 차시마다 하고, 쓴 스크립트를 모두 밝힌다(F4).

### F4 근거 표시

- AI 응답에는 **어떤 스크립트를 썼는지**(과목, 주차·차시, 제목)를 붙인다(S7-3). 내용의 근거 위치는 스크립트의 시각으로 `3주차 강의 12:30`처럼 쓴다([learning_adapters §3.2](../layers/06_learning_adapters.md#32-전사) 출력 형식).
- 이것은 `ToolGuide`의 응답 원칙 R1(출처를 붙인다)을 학습 결과물에 적용한 것이다([entrypoints §6](../layers/04_entrypoints.md#6-toolguide)). 학습 결과물의 출처 표기 방식을 `ToolGuide` 원문에 함께 적는다(추론).
- `Peer` 스크립트를 썼으면 요약에 기댄 결과임과 원본 파일이 앱 밖에서 바뀌었음을 밝힌다(R3를 학습 결과물에 적용, 추론).

## 4. 수용 기준

| # | 기준 | 확인 방법 | 시나리오 |
|---|---|---|---|
| AC1 | "3주차 요약해 줘"에 대한 응답이 3주차 스크립트를 근거로 하고, 쓴 스크립트(과목, 주차·차시, 제목)가 응답에 보인다 | FS-13으로 만든 스크립트가 있는 상태에서 질문한다 | S7-3 ★ |
| AC2 | 퀴즈와 예상 시험지를 요청해도 대화로 결과가 나오고, 쓴 스크립트가 모두 보인다 | 두 요청을 각각 보낸다 | S7-3 ★ |
| AC3 | 스크립트가 없는 주차를 물으면 AI가 내용을 지어내지 않고 없다고 답하며, 만들 수 있다고 안내한다 | 스크립트가 없는 주차로 질문한다 | S7-3 |
| AC4 | 앱이 만든 뒤 바뀌지 않은 스크립트를 조회하면 등급이 `Official`이고 원문이 넘어가며, 그 대화에 시점 경고가 없다 | `cdx` 조회 결과의 등급과 hook 기록을 본다 | S7-3 |
| AC5 | 스크립트 파일을 1바이트 바꾸면 조회 등급이 `Peer`가 되고, `cdx` 결과에 원문 대신 격리 요약이 들어가며, 그 대화의 첫 위험 도구 호출이 한 번 거부된다 | 파일을 바꾼 뒤 질문하고 `cdx` 출력과 hook 기록을 본다 | S7-3 |
| AC6 | 스크립트와 앱 데이터의 해시 기록을 함께 바꿔도(HMAC은 다시 계산할 수 없음) `Peer`가 된다 | 기록의 해시를 바꾼 파일의 해시로 고친 뒤 조회한다(메모리 `SecretStore`) | — |
| AC7 | 학습 자료 폴더에 학생이 직접 넣은 `.txt`는 `Peer`로 다뤄진다 | 기록 없는 파일을 같은 이름 규칙 위치에 두고 조회한다 | — |
| AC8 | 학습 자료 폴더 밖 경로를 인자로 주면 거부되고 파일을 읽지 않는다 | `cdx`에 `../` 경로와 절대 경로를 넣는다 | — |
| AC9 | `Peer` 스크립트로 공부를 요청하면 응답에 요약에 기댄 결과이고 원본 파일이 앱 밖에서 바뀌었다는 안내가 함께 보인다 | 기록이 없는 스크립트로 요청하고 응답 확인 | S7-3 ★ |

★ 실제 학교 계정과 서버가 있어야 확인할 수 있다(실제 강의 동영상으로 만든 스크립트가 필요하다).

## 5. User Flow (UF-14)

이 기능의 [Design Process ①](../03_design_process.md)에서 그린다. 그릴 갈래: `Official` 스크립트로 답하기(F1~F4), 스크립트 없음, `Peer` 스크립트(격리 요약과 시점 경고).

## 6. 미확인 항목

- **`Peer` 스크립트의 원문 보기**: 격리 요약을 쓸 수 없을 때 FS-09 F5는 "원문은 앱에서 보기"를 주지만, 우측 패널의 원문 보기([FS-09](FS-09_notices_and_peer_safety.md) F6)는 게시판 글을 위한 것이라 스크립트 파일은 대상이 아니다. 스크립트도 우측 패널에서 보일지, 파일 위치만 알려 줄지 정한다
- **"요약·퀴즈 생성"이 유스케이스인지**: [application §3](../layers/02_application.md#3-유스케이스-후보)은 `usecases/learning`에 "요약·퀴즈 생성"을 둔다. 그러나 다른 근거는 모두 대화 AI의 일로 읽힌다. 이 FS는 **대화 AI가 만들고, 코어는 스크립트 조회만 한다**고 보았다(F3).
  - [UX Strategy §11](../06_ux_strategy.md#11-대응표): "학습: 요약·퀴즈 생성 | S7-3 | 대화". S7-3 성공 상태: "대화로 결과가 나오고, 어떤 스크립트를 썼는지 보인다".
  - [UX Strategy §5](../06_ux_strategy.md#5-경험-원칙) P1: "대화로 끝낼 수 있으면 대화로 한다".
  - [application §4.2](../layers/02_application.md#42-ai)의 실행 모드 "요약"과 [ai_adapters §3](../layers/05_ai_adapters.md#3-실행-모드)의 요약 세션은 `Peer` 원문 격리 요약용이다. 학습 요약용 세션 규칙은 없다.
  - [application §4.3](../layers/02_application.md#43-학습)의 학습 포트에는 생성 포트가 없고, 결과를 저장할 포트·이름 규칙(domain §4.2의 종류는 동영상·슬라이드·스크립트뿐)도 없다.
  - 제안: application §3의 "요약·퀴즈 생성"을 "학습 결과물 조회(스크립트, 신뢰 등급 포함)" 유스케이스로 바꾸고, 대응하는 `cdx` 명령을 [entrypoints §4](../layers/04_entrypoints.md#4-cdx-명령)에 둔다. 이 조회 유스케이스와 `cdx` 명령은 지금 아키텍처에 이름이 없다 → [UX Strategy §12](../06_ux_strategy.md#12-아키텍처에-올릴-것) 후보
- **AI가 스크립트 파일을 직접 읽는 경로**: 대화 모드 AI는 사용자 설정의 도구(Read, Bash 등)를 그대로 쓴다([ai_adapters §3](../layers/05_ai_adapters.md#3-실행-모드)). 스크립트는 사용자 폴더의 평범한 파일이므로, AI가 `cdx`를 거치지 않고 파일을 직접 읽으면 등급 판정·격리 요약·시점 경고가 모두 적용되지 않는다. [security §2](../cross_cutting/01_security.md#2-주입당한-ai가-쓸-수-있는-통로) 통로 F의 대응("결과물 등급은 앱이 남긴 해시와 맞을 때만 `Official`")은 `cdx` 경로에서만 효과가 있다. `ToolGuide`에 "학습 결과물은 `cdx`로 읽는다"를 넣는 것으로 충분한지, 수용한 위험([security §6](../cross_cutting/01_security.md#6-수용한-위험))에 올릴지 security 문서에서 정한다
- **`Peer` 스크립트로 공부할 때의 품질**: `Peer`면 원문 대신 격리 요약만 넘어가므로, 요약·퀴즈·예상 시험지가 요약의 요약이 된다. 학생에게 FS-13으로 다시 만들기를 권하는 안내를 둘지 정한다. 다시 만들면 동영상에서 새로 뽑으므로 `Official`로 돌아온다([security §4.1](../cross_cutting/01_security.md#41-신뢰-등급))
- **HMAC 키를 읽지 못할 때**: 화면 잠금 등으로 `SecretStore`가 실패하면 등급을 `Peer`로 볼지(안전한 쪽), 잠시 뒤 다시 시도할지. FS-03 F7은 키체인 `Locked`를 로그아웃으로 다루지 않고 다시 읽는다. 같은 방식을 쓸지 정한다
- **스크립트 길이**: 30분 강의 스크립트를 `cdx` 출력 하나로 통째로 넘길지, 시각 구간으로 나눠 받게 할지. 여러 차시(시험 범위)를 쓸 때의 대화 문맥 크기와 함께 정한다
- **슬라이드 PDF의 OCR 글자**: S7-3은 스크립트만 말한다. 슬라이드 PDF의 OCR 글자도 공부 근거로 넘길지, 넘긴다면 같은 등급 규칙을 쓰는지 정한다([security §2](../cross_cutting/01_security.md#2-주입당한-ai가-쓸-수-있는-통로) 통로 F는 슬라이드 PDF도 포함한다)
- **만든 요약·퀴즈 저장**: 대화 기록 밖에 파일로 남기는 기능은 아키텍처에 없다. 필요하면 [UX Strategy §12](../06_ux_strategy.md#12-아키텍처에-올릴-것) 후보로 올린다
- **경로 인자 거부와 격리 요약 실패의 application 오류**: 학습 자료 폴더 밖 경로를 `Rejected(PolicyDenied)`로 볼지, 격리 요약 세션을 띄우지 못했을 때 원문을 넘기지 않고 어떤 오류로 끝낼지([application §4.5](../layers/02_application.md#45-application-오류))
- **학습 결과물의 출처 표기**: F4의 `3주차 강의 12:30` 형식을 `ToolGuide` 원문에 넣을지, AI용 Presenter가 결과 JSON에 표기용 문자열을 넣을지
