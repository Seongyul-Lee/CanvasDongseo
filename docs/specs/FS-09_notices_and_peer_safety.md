# FS-09 공지 조회와 `Peer` 안전

| 항목 | 내용 |
|---|---|
| 독자 | 개발자 본인, 후속 문서·구현을 돕는 AI 에이전트 |
| 상태 | 초안 |
| 시나리오 | S4-3, S5-1, S5-2, S5-3 ([UX Strategy §4](../06_ux_strategy.md#4-actor와-시나리오)) |
| 화면 | 대화, 우측 패널(`Peer` 원문) ([UX Strategy §7.1](../06_ux_strategy.md#71-내비게이션-골격), [§7.2](../06_ux_strategy.md#72-mvp-화면)) |
| 유스케이스 | 조회 묶음의 공지 조회(학교·학과·과목, 게시판), 대화 안전 묶음(`Peer` 읽음 기록, hook 판정, 격리 요약) ([application §3](../layers/02_application.md#3-유스케이스-후보)). 이름은 미정 |
| 근거 | [06_school_site](../layers/data_access/06_school_site.md), [02_canvas](../layers/data_access/02_canvas.md), [03_learningx](../layers/data_access/03_learningx.md), [security §4](../cross_cutting/01_security.md#4-프롬프트-주입-대응-r3), [entrypoints §5·§7](../layers/04_entrypoints.md#7-hook-진입점-cdx-hook), [ai_adapters §5](../layers/05_ai_adapters.md#5-hook-설정과-격리-요약), [presentation §2.3](../layers/03_presentation.md#23-신뢰하지-않는-html과-webview-보안) |

> **이 문서의 역할**: 학교·학과·과목 공지와 게시판 글을 대화로 조회하는 기능, 그리고 다른 사람이 쓴 글(`Peer`)을 AI에 안전하게 넘기는 장치(격리 요약, 우측 패널 원문, 시점 경고)의 동작과 수용 기준을 정한다.
> 경로와 HTML 형식은 [06_school_site](../layers/data_access/06_school_site.md)·[02_canvas](../layers/data_access/02_canvas.md)·[03_learningx](../layers/data_access/03_learningx.md), 신뢰 등급의 판단 기준과 장치의 근거는 [security §4](../cross_cutting/01_security.md#4-프롬프트-주입-대응-r3), hook 형식은 [ai_adapters §5](../layers/05_ai_adapters.md#5-hook-설정과-격리-요약)가 맡는다. 학과 공지에서 어느 학과를 조회할지는 [FS-05](FS-05_departments.md) F5가 정한다.

## 1. 범위

| 하는 것 | 하지 않는 것 |
|---|---|
| 학교 공지(표 형식 게시판) 목록·검색·본문 | 사진형·영상형 게시판(대학뉴스, TV 뉴스, 카드뉴스). 파서가 정해지지 않았다([06_school_site §2](../layers/data_access/06_school_site.md#2-학교-공지)) |
| 학과 공지 목록·검색·본문(학과 결정은 FS-05) | 학사일정·장학 안내 같은 안내 페이지(게시판이 아님, 같은 절) |
| Canvas 과목 공지 목록·본문 | 게시판·토론 글쓰기, 댓글, 메시지 보내기([data_access §1.3](../layers/data_access/README.md)) |

| `Peer` 원문을 우측 패널에서 보여 주기 | 공지 첨부파일 내려받기(링크만 준다, §6) |
| `Peer`를 읽은 대화의 시점 경고(hook post·pre) | 위험 도구를 상시 차단하기. F7은 한 번만 거부하고 그 뒤에는 허용한다([security §4.2](../cross_cutting/01_security.md#42-장치)) |
| | 학습 결과물의 `Peer` 판정(FS-13·FS-14) |

## 2. 기능 요구사항

### F1 학교 공지 (S5-1)

- **입력**: 게시판(레지스트리 키), 선택으로 분류(`CgCode`), 검색어, 쪽 번호. 게시판 코드는 레지스트리(데이터)에 있고 코드에 박지 않는다([06_school_site §2](../layers/data_access/06_school_site.md#2-학교-공지)).
- **목록 출력**(글마다): 게시판 이름, 분류(있으면), 제목, 게시일, 원문 링크(`mode=view&idx=`), 고정 공지 여부. 결과 전체에 조회 시각.
- **고정 공지**: 모든 쪽·검색 결과 맨 위에 반복되므로 따로 표시하고, 같은 `idx`를 두 번 세지 않는다. 검색어와 맞지 않는 고정 공지는 검색 결과에서 뺀다(추론, §6).
- **검색**: 학교 CMS는 띄어쓴 단어를 OR로 찾는다. 여러 단어를 모두 담은 글을 찾으려면 단어 하나로 검색하고 나머지 단어는 코어가 거른다([06_school_site §1](../layers/data_access/06_school_site.md#1-공통-학교-홈페이지-cms-2026-11-08-확인)).
- **본문 출력**: 제목, 작성 정보, 본문 글자, 첨부 목록(파일 이름·크기·링크).
- 학교·학과 공지는 `Official`이다. 대화 AI에 그대로 준다.

### F2 학과 공지 (S5-2, S5-3)

- **입력**: 학과(레지스트리 키, 없으면 설정의 학과, [FS-05](FS-05_departments.md) F5), 검색어, 쪽 번호.
- **출력**: 학과별로 묶어 학과 이름과 공지 목록(F1과 같은 칸). 학과 하나에 게시판이 여럿이면 게시판 이름을 함께 준다.
- "최근 공지"는 각 공지 게시판의 첫 쪽이다(추론, §6). 목록은 학과 사이트의 최신 글과 같아야 한다(S5-2 점검).
- 학교 공지와 같은 CMS 파서를 쓴다. 목록 형식이 아니면 빈 목록이 아니라 `SourceChanged`다(예: 공지 게시판이던 `pCode`가 다른 페이지로 바뀐 경우, [06_school_site §2](../layers/data_access/06_school_site.md#2-학교-공지)).

### F3 과목 공지

- **입력**: 과목 ID(없으면 모든 수강 과목). 과목 ID는 [FS-08 F7](FS-08_todo_and_courses.md#f7-수강-과목-목록)의 목록에서 온다.
- Canvas 과목 공지는 기간을 주지 않으면 최근 14일만 온다. 그 과목 학기의 시작·끝을 기간으로 넣는다([02_canvas §2](../layers/data_access/02_canvas.md#2-rest-경로)). 학기 기간이 없으면 §6.
- **출력**: 과목명, 제목, 게시일, 원문 링크, 본문(요청 시). `Official`이다.
- 공지에 학생이 단 댓글은 `Peer`이고 F4·F5를 따른다(추론, §6).

### F4 게시판 글과 신뢰 등급 (S4-3)

- 대상: Canvas 토론 글·댓글(`discussion_topics/{id}/view`), LearningX 게시판의 글. LearningX 게시글 경로는 아직 확인하지 못했다([03_learningx 미확인](../layers/data_access/03_learningx.md#미확인-항목)). 확인 전에는 게시판 목록만 준다.
- 신뢰 등급은 DS가 **구조로** 정한다(경로 종류, 작성자 ID와 로그인 ID 비교). 내용을 보고 정하지 않는다([security §4.1](../cross_cutting/01_security.md#41-신뢰-등급)). 출력 DTO의 항목마다 등급이 붙는다.
- `Peer` 항목은 F5의 격리 요약을 거쳐서만 AI에 간다.

### F5 격리 요약

- `Peer` 원문은 대화 AI에 주지 않는다. 코어 유스케이스가 **도구 없는 격리 세션**(`--tools ""`, [ai_adapters §5](../layers/05_ai_adapters.md#5-hook-설정과-격리-요약))을 직접 띄워 원문을 넣고 요약만 받는다. 이 세션은 대화 AI와 문맥을 나누지 않는다.
- `cdx`가 돌려주는 `Peer` 항목에는 원문 대신 요약, 등급 `Peer`, 원문 보기용 항목 ID가 들어간다([entrypoints §5](../layers/04_entrypoints.md#5-ai용-presenter)).
- 요약은 원문에서 나온 것이므로 그 자체도 `Peer`로 다룬다(F7의 경고 대상).
- 제목·작성자 이름처럼 원문의 다른 칸도 원문으로 보고 요약에 넣거나 뺀다(추론, §6).
- 격리 세션을 쓸 수 없으면(`AiUnavailable`, 시간 초과) 원문을 넘기지 않는다. 그 항목은 "요약하지 못함, 원문은 앱에서 보기"로 돌려준다(추론, §6).

### F6 원문 보기 (우측 패널)

- 대화 안의 `Peer` 결과에는 앱이 붙인 "요약임" 표시와 "원문 보기" 버튼이 있다(P2, R3). AI가 쓴 말이 아니라 앱의 말로 보인다. 이 표시를 대화에 어떻게 넣는지는 §6.
- 버튼을 누르면 우측 패널(`RightPanelSheet`)이 열리고 원문을 보인다. 패널은 학생이 누를 때만 열린다.
- 원문 HTML은 Presenter(Rust)에서 허용 목록으로 정화하고(스크립트, 이벤트 속성, `javascript:` 링크, iframe, form 제거), 스크립트를 허용하지 않는 샌드박스 iframe에 그린다. 외부 이미지는 허용 목록 호스트만 불러온다([presentation §2.3](../layers/03_presentation.md#23-신뢰하지-않는-html과-webview-보안)).
- 원문 안의 링크는 OS 브라우저로 연다. 앱 WebView 안에서 이동하지 않는다.
- 원문은 로그, `cdx` 출력, 대화 기록에 남기지 않는다([security §3](../cross_cutting/01_security.md#3-지킬-것과-강제하는-곳) 기록 규칙).

### F7 시점 경고 (hook)

[entrypoints §7](../layers/04_entrypoints.md#7-hook-진입점-cdx-hook)의 판정을 기능으로 옮긴 것이다. 판정은 코어가 하고 `cdx hook`은 전달만 한다.

| 시점 | 조건 | 코어 판정 | AI가 받는 것 |
|---|---|---|---|
| `cdx` 실행 직후(`cdx hook post`) | 결과에 `Peer` 항목이 있음 | 대화를 "`Peer` 읽음"으로 기록, `warn(context)` | 도구 결과 바로 뒤의 경고 컨텍스트 |
| `cdx` 실행 직후 | `Peer` 없음 | `pass` | 없음 |
| 위험 도구 호출 직전(`cdx hook pre`) | "`Peer` 읽음"이고 아직 거부하지 않음 | `deny_once(reason)`, 거부했다고 기록 | 호출 거부와 이유(경고) |
| 위험 도구 호출 직전 | 이미 한 번 거부함, 또는 `Peer`를 읽지 않음 | `pass` | 없음 |

- 거부는 대화마다 한 번이다. AI가 사용자 요청임을 확인하고 같은 호출을 다시 하면 통과한다(S4-3 "시점 경고가 한 번 나온다").
- `Peer`를 읽지 않은 대화에는 아무것도 넣지 않는다.
- 코어에 연결할 수 없으면 통과시킨다(앱이 꺼져 있을 때 다른 작업을 막지 않는다).
- 판정과 전달 여부를 코어가 기록한다. hook 메시지는 stream-json에 나오지 않으므로 이 기록으로 확인한다.
- 대화 상태(`Peer` 읽음, 거부함)는 대화 ID로 묶는다. 대화 ID는 IPC 토큰에서 코어가 정한다([entrypoints §3](../layers/04_entrypoints.md#3-ipc)).

## 4. 수용 기준

| # | 기준 | 확인 방법 | 시나리오 |
|---|---|---|---|
| AC1 | 장학금 공지를 물으면 공지 제목, 게시일, 원문 링크가 보이고, 링크를 누르면 OS 브라우저에서 그 공지가 열린다 | 실제 대화에서 질문하고 링크를 누른다 | S5-1 ★ |
| AC2 | 고정 공지가 여러 쪽에 반복돼도 결과에 한 번만 있고 고정 공지로 표시된다 | 저장한 목록 HTML 두 쪽으로 파서 테스트 | S5-1 |
| AC3 | 띄어쓴 두 단어로 찾으면 두 단어를 모두 담은 글만 나온다 | 저장한 검색 결과 HTML로 테스트 | S5-1 |
| AC4 | 게시판 주소가 목록이 아닌 페이지를 돌려주면 빈 목록이 아니라 `SourceChanged`가 되고, 다른 게시판 조회는 성공한다 | 저장한 다른 페이지 HTML로 테스트 | S2-7 |
| AC5 | 우리 학과 최근 공지를 물으면 학과 이름과 목록이 보이고, 목록이 학과 사이트의 최신 글과 같다 | 실제 대화에서 질문하고 학과 사이트와 비교한다 | S5-2 ★ |
| AC6 | "간호학과 공지 보여 줘"에 간호학과 공지가 나온다 | 실제 대화에서 질문한다 | S5-3 ★ |
| AC7 | 과목 공지는 학기 기간으로 조회돼 14일보다 오래된 공지도 나온다 | 요청 기간을 확인하는 DS 테스트 + 실제 과목 | — ★ |
| AC8 | `Peer` 글을 물으면 `cdx` 출력에 원문 글자가 없고, 요약·`Peer` 등급·원문 보기 ID가 있다 | 표지 문자열을 넣은 고정 글로 AI용 Presenter·유스케이스 테스트(출력에서 표지 검색) | S4-3 |
| AC9 | 격리 요약 세션은 도구 없이 실행되고 대화 AI와 문맥을 나누지 않는다 | 격리 세션 실행 인자 테스트 | S4-3 |
| AC10 | 격리 요약이 실패해도 `cdx` 출력에 원문이 들어가지 않는다 | 요약 포트가 실패하는 테스트 | S4-3 |
| AC11 | 대화에 `Peer` 결과가 나오면 앱이 붙인 "요약임" 표시와 원문 보기 버튼이 AI 메시지와 구별되어 보이고, 누르면 우측 패널에 원문이 열린다 | 실제 앱에서 게시판 글을 묻는다 | S4-3 ★ |
| AC12 | 원문에 스크립트·이벤트 속성·`javascript:` 링크·iframe·form을 넣어도 패널에서 실행·표시되지 않고, iframe에 `allow-scripts`가 없다 | 악성 표본으로 정화 Presenter 테스트 + 패널 DOM 확인 | S4-3 |
| AC13 | 패널 안의 링크를 누르면 OS 브라우저로 열리고 앱 창은 그대로다 | 실제 앱에서 누른다 | S4-3 ★ |
| AC14 | `Peer`를 읽은 대화에서 첫 위험 도구 호출은 이유와 함께 한 번 거부되고, 같은 호출을 다시 하면 통과하며, 그 뒤 같은 대화에서 다시 거부되지 않는다 | `cdx hook` 입력을 고정한 판정 테스트 + 실제 대화의 코어 기록 | S4-3 ★ |
| AC15 | `Peer`를 읽지 않은 대화에서는 hook이 아무것도 넣지 않고 위험 도구도 거부하지 않는다 | 판정 테스트 | S4-3 |
| AC16 | 앱(코어)이 꺼져 있으면 `cdx hook pre`가 통과를 돌려준다 | 코어 없이 `cdx hook pre`를 실행한다 | — |
| AC17 | 학교·학과·과목 공지는 `Official`로 표시되고 요약 없이 AI에 간다 | AI용 Presenter 테스트 | S5-1, S5-2 |
| AC18 | `Peer` 원문이 로그, 대화 기록, 앱 데이터 파일에 남지 않는다 | 표지 문자열을 넣은 글을 조회·패널 열기 뒤 해당 위치에서 검색 | S4-3 |
| AC19 | 신뢰 등급은 구조로만 정해진다. 토론·게시판 경로의 글과, 작성자 ID가 로그인 ID와 다른 글은 내용과 관계없이 `Peer`이고, 같은 글의 본문을 바꿔도 등급이 바뀌지 않는다 | DS 응답을 고정한 등급 판정 테스트 | S4-3 |

★ 실제 학교 계정과 서버(학교 공지는 공개 사이트)가 있어야 확인할 수 있다. 실제 대화로 확인하는 기준은 유료 Claude 계정도 필요하다.

## 5. User Flow (UF-09)

이 기능의 [Design Process ①](../03_design_process.md)에서 그린다. 그릴 갈래: 학교 공지 찾기(검색, 링크 열기), 학과 공지(내 학과, 다른 학과), 과목 공지, `Peer` 글(격리 요약 → 요약 표시 → 원문 패널 열기, 요약 실패), 시점 경고(post 경고 → 위험 도구 첫 호출 거부 → 다시 호출 통과).

## 6. 미확인 항목

- **신뢰 등급 판단 기준의 해석.** [security §4.1](../cross_cutting/01_security.md#41-신뢰-등급)은 `Peer`를 "경로 종류(토론·게시판·메시지·그룹) **또는** 작성자 ID ≠ 로그인 ID"로, `Official`을 "학교·교수가 쓴 글(과목 공지 …)"로 정한다. 그런데 과목 공지는 교수가 썼으므로 작성자 ID ≠ 로그인 ID이고, [02_canvas §2](../layers/data_access/02_canvas.md#2-rest-경로)는 "공지도 토론 주제로 조회된다"(`discussion_topics/{topic_id}`)고 쓴다. 글자 그대로 읽으면 과목 공지도 `Peer`가 된다. "작성자 ID" 조건을 어느 경로에만 쓰는지, 공지를 `discussion_topics` 경로로 읽을 때 등급을 무엇으로 볼지 security 문서에서 정해야 한다. 교수가 연 토론 주제 본문의 등급도 같다
- **대화 안 "요약임" 표시와 원문 보기 버튼을 넣는 방법.** [UX Strategy §7.2](../06_ux_strategy.md#72-mvp-화면)는 "`Peer` 요약 표시와 원문 보기"를 앱 컴포넌트로 두고, P2는 앱의 말로 보이게 하라고 한다. 그러나 대화에 이 앱 요소를 언제·무엇으로 넣는지(코어가 대화 ID별로 `Peer`를 돌려준 기록에서 만드는지, AI 이벤트 `ToolResult`에서 만드는지, AI가 쓴 요약 문장과 어떻게 짝짓는지)는 [presentation](../layers/03_presentation.md)·[application §4.2](../layers/02_application.md#42-ai)에 없다. 아키텍처에 없음 → UX Strategy §12 후보
- 원문 보기 때 원문을 어디서 얻는지(코어가 메모리에 잠시 두는지, 항목 ID로 다시 가져오는지). 기록 규칙상 디스크에 남기지 않는다고 보면 다시 가져오기가 된다(추론). 앱을 다시 시작한 뒤 지난 대화의 원문 보기를 누를 때도 같다
- 시점 경고의 "한 번"의 범위. [security §4.2](../cross_cutting/01_security.md#42-장치)는 "그 대화의 첫 위험 호출"이라 쓴다. 거부한 뒤 같은 대화에서 새 `Peer`를 또 읽으면 다시 거부할지 정하지 않았다
- 대화 상태(`Peer` 읽음, 거부함)를 앱을 다시 시작해도 유지할지. 지난 대화를 다시 열면(S9-3) 요약이 맥락에 남아 있으므로 유지해야 한다고 본다(추론). 저장 위치(`ConversationRepository`)도 정하지 않았다
- 위험 도구 목록의 기준([security §7](../cross_cutting/01_security.md#7-미확인-항목))
- 격리 요약을 쓸 수 없을 때 원문 없이 "앱에서 보기"만 주는 동작(F5, 추론). 원문을 넘기지 않는다는 규칙에서 나온 것이지만 문서에 적힌 동작은 아니다
- `Peer` 원문의 제목·작성자 이름(학생 이름)을 AI에 줄지. 제목도 다른 사람이 쓴 글이라 주입 경로가 될 수 있다(F5, 추론)
- 글이 많은 게시판을 물으면 글마다 격리 세션을 띄우게 된다. 한 번에 요약할 글 수의 상한, 여러 글을 한 세션에 묶을지, 요약 결과를 기억해 둘지 정하지 않았다(AI 사용 한도와 응답 시간에 영향)
- LearningX 게시판 글 목록·본문 경로([03_learningx 미확인](../layers/data_access/03_learningx.md#미확인-항목)). 확인 전에는 게시판 목록만 주고 글 조회는 `NotAvailable`로 둘지(추론)
- 메시지(`conversations`)·그룹도 `Peer`인데([security §4.1](../cross_cutting/01_security.md#41-신뢰-등급)), 메시지 조회 기능은 [UX Strategy §11](../06_ux_strategy.md#11-대응표) 대응표와 FS 목록에 없다. 조회 기능을 둘지 정해야 한다. 두면 이 FS의 F4~F7을 그대로 적용한다
- 학외공지(동서광장, `square01`) 게시판의 작성자가 학교 밖 사람일 수 있다. 이 게시판을 `Official`로 볼지 확인한다
- 과목 공지에 학생이 단 댓글을 조회할지와 그 등급(F3, `Peer`로 추론)
- 학기 기간(`term.start_at`·`end_at`)이 비어 있는 과목의 과목 공지 기간(F3)
- 고정 공지를 검색 결과에서 뺄지(F1, 추론)와 "최근 공지"의 개수(F2, 첫 쪽 15개로 추론)
- 공지 첨부파일은 링크만 주고 OS 브라우저에 맡긴다고 썼다. 앱이 받아 정해진 폴더에 저장하는 기능은 [FS-12](FS-12_material_download.md)(강의 자료·동영상) 범위에 없다
- **학교 로그아웃 상태의 공지 조회.** 학교·학과 공지는 로그인 없이 공개인데([06_school_site §1](../layers/data_access/06_school_site.md#1-공통-학교-홈페이지-cms-2026-11-08-확인)), [UX Strategy S10-3](../06_ux_strategy.md#a10-앱의-데이터보안-정책이-궁금한-사람) 점검 방법은 "로그아웃 뒤 데이터 질문에 연결 안내가 나오고"라고 쓴다. 공지 질문에도 연결 안내를 낼지, 로그인 없이 답할지 정해야 한다([FS-05](FS-05_departments.md) §6과 같은 항목)
