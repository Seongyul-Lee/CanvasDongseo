## 2. 기능 요구사항

### F1 조회 경로

- AI는 `cdx` 명령으로 조회한다. 명령 하나가 유스케이스 하나에 대응한다([entrypoints §4](../layers/04_entrypoints.md#4-cdx-명령)). 명령 목록은 아직 정하지 않았다([entrypoints §9](../layers/04_entrypoints.md#9-미확인-항목)).
- 명령 인자에 **학번·이름이 없다**. 연도·학기 같은 조회 조건만 받는다.
- 결과는 출력 DTO → AI용 Presenter → JSON으로 AI에 간다([entrypoints §5](../layers/04_entrypoints.md#5-ai용-presenter)). 내부 URL 쿼리, 쿼리 토큰, 요청 단계 정보는 내보내지 않는다.
- 학생지원시스템에는 **허용 목록에 이름이 있는 조회 서비스만** 호출한다([07 §3.5](../layers/data_access/07_student_portal.md#35-앱이-지킬-것)). 쿼리 토큰은 화면 HTML에서 읽고 앱에 고정하지 않는다([07 §3.2](../layers/data_access/07_student_portal.md#32-화면과-서비스-선언)).

### F2 성적·이수 학점

- **출처**: 학생지원시스템. 대상 화면은 [07 §4](../layers/data_access/07_student_portal.md#4-메뉴별-서비스-목록)의 "앱에서 쓸 만한 조회 화면" 중 성적(중간성적 `AE011`, 확정전 성적 `AE010`, 성적조회 `AE020`)과 졸업 요건(졸업시뮬레이션 `AE040`)이다. 쓸 서비스와 응답 필드는 [07 §5](../layers/data_access/07_student_portal.md#5-조회-허용-목록과-응답-필드-2026-11-12-실측)의 허용 목록에 있다.
- **로그인**: 학생지원시스템 세션이 없거나 끝났으면 FS-04 F1·F4대로 로그인 창을 띄우고, 로그인 뒤 원래 요청을 다시 실행한다.
- **출력**: 학기별 과목 성적, 학기·누적 평점, 이수 학점. 확정 전 성적과 확정 성적을 구별한다. 학기별 과목 성적은 `AE020`의 과목별 `LIST`, 학기·누적 평점과 이수 학점은 `AE020`의 학기별 `LIST`와 `SELECT_GRADE_INFO`, 졸업 요건은 `AE040`의 시뮬레이션 결과에서 온다([07 §5](../layers/data_access/07_student_portal.md#5-조회-허용-목록과-응답-필드-2026-11-12-실측)). 중간성적(`AE011`)과 확정전 성적(`AE010`)의 목록은 조회 기간에만 온다. 어느 필드를 출력 DTO에 담을지는 구현 때 정한다(§6).
- 성적 공개 기간 밖이라 결과가 없으면 없다고 돌려준다. 다른 학기 값으로 채우지 않는다(R2).

### F3 학적 정보

- **출처**: 학생지원시스템의 사용자·학적 정보(`SELECT_USER_INFO`, `SELECT_STD_INFO`, 학생기본정보 `AB010`, 지도교수 `SELECT_MY_TUTOR`, [07 §3.3](../layers/data_access/07_student_portal.md#33-조회-요청)).
- **출력**: 학적 상태, 학년, 대학·전공(부전공·복수전공 포함), 지도교수.
- 학생기본정보의 응답에 들어 있는 은행과 계좌번호는 가져오지 않는다. Source가 버리므로 출력 DTO와 AI용 JSON에 나올 수 없다([07 §3.5](../layers/data_access/07_student_portal.md#35-앱이-지킬-것)).
- 로그인은 F2와 같다.
- 이 값은 학과 공지의 학과 설정에 쓰지 않는다. 학과는 학생이 목록에서 고른다([FS-05](FS-05_departments.md)).

### F4 출결

- **기준 출처**: 학생지원시스템 과목출결조회(`AC110`, [07 §4](../layers/data_access/07_student_portal.md#4-메뉴별-서비스-목록))다. 출결의 최종 기준이 학생지원시스템이기 때문이다([domain §3](../layers/01_domain.md#3-엔티티-후보), [04 §1](../layers/data_access/04_smart_attendance.md#1-접근-경로)).
- **참고 출처**: 스마트출결. 그 과목이 스마트출결을 쓰는 수업이면, 학생지원시스템에 아직 옮겨지지 않은 전자출결 기록(전자출결은 다음 날 새벽에 옮겨진다, [04 §1](../layers/data_access/04_smart_attendance.md#1-접근-경로))을 스마트출결에서 읽어 **참고**로 덧붙인다. 참고 기록은 기준 기록과 구별해 "학생지원시스템 반영 전"으로 표시한다. 같은 수업 일시에 두 값이 다르면 학생지원시스템 값을 쓴다.
- **로그인**: 학생지원시스템 로그인이 필요하다. 세션이 없거나 끝났으면 FS-04 F1·F4대로 로그인 창을 띄우고, 로그인 뒤 원래 요청을 다시 실행한다. 스마트출결 참고 기록은 학교 계정 세션(FS-03)으로 읽고, 학교 세션이 끝났으면 FS-03 F5의 OTP 흐름을 탄다. 스마트출결 참고 기록을 읽지 못해도 기준 기록은 돌려준다(부분 결과, [FS-08 F5](FS-08_todo_and_courses.md#f5-출처별-부분-실패)).
- **범위**: 과목을 지정하면 그 과목, 지정하지 않으면 수강 중인 모든 과목. 과목 목록은 [FS-08 F7](FS-08_todo_and_courses.md#f7-수강-과목-목록)이다.
- **출력**: 과목별로 수업 일시마다 출석·지각·결석과, 과목별 집계([domain §4](../layers/01_domain.md#4-업무-규칙-후보) 출결 집계). 항목마다 출처(학생지원시스템, 스마트출결 참고)를 붙인다(F5).
- 읽기만 한다. 출결 등록 요청은 보내지 않는다.

### F5 출처와 조회 시각 (R1)

- 성적·이수 학점·출결은 목록이나 수치이므로, 출력 DTO와 AI용 JSON에 **출처**(학생지원시스템, 스마트출결)와 **조회 시각**(학교 서버에서 받은 시각)을 넣는다. `ToolGuide`의 응답 원칙([UX Strategy §9](../06_ux_strategy.md#9-ai-응답-경험-원칙) R1, [entrypoints §6](../layers/04_entrypoints.md#6-toolguide))이 이 값으로 답에 붙인다.
- 원문 링크는 학생이 웹에서 같은 값을 볼 수 있는 곳으로 준다. 스마트출결은 그 과목의 스마트출결 도구 화면(추론), 학생지원시스템은 무엇을 줄지 미정이다(§6).
- 학적 상태처럼 짧은 답에는 출처만 붙인다.
- 학교 데이터를 추측하지 않고 조회한다. 결과가 없으면 없다고 답한다(R2).

### F6 본인 데이터만 (IDOR 방어)

- 학생지원시스템 요청의 학번은 FS-04 F5대로 로그인 학번만 쓴다.
- 스마트출결 요청의 `user_login`·`user_name`도 로그인 세션의 값으로만 채우고, 응답의 학번이 로그인 학번과 다르면 버린다([04 §1](../layers/data_access/04_smart_attendance.md#1-접근-경로)).
- 학생이나 AI가 다른 학번을 말해도 그 값은 요청에 들어갈 경로가 없다. 그런 요청은 앱이 하지 않는 일로 거절한다(R4).

| AC9 | 응답의 학번이 로그인 학번과 다르면 그 값이 답에 나오지 않는다 | 응답을 고정한 테스트(학생지원시스템, 스마트출결 각각) | — |
| AC10 | 허용 목록에 없는 학생지원시스템 서비스는 호출되지 않는다. 허용 목록에 쓰기 서비스(`INSERT`·`UPDATE`·`DELETE` 종류, `UPSERT_*`, `INS_CERT_NO`)가 없다 | 허용 목록 검사 테스트 + 목록 밖 서비스 호출 시도 테스트 | — |
| AC11 | "학점포기 신청해 줘"에 거절과 이유가 나오고, 학교로 요청이 나가지 않는다 | 대화 + 요청 기록 확인 | — ★ |
| AC12 | 스마트출결을 쓰는 과목에서 학생지원시스템에 아직 옮겨지지 않은 전자출결 기록은 "학생지원시스템 반영 전"으로 구별돼 덧붙고, 같은 일시에 값이 다르면 학생지원시스템 값이 나온다. 스마트출결을 쓰지 않는 과목은 기준 기록만 나오고 오류 안내가 없다 | 두 출처 응답을 고정한 유스케이스 테스트 | S6-2 |
| AC13 | 쿼리 토큰을 찾지 못하면 학교 사이트가 바뀌었다는 안내가 나오고, 로그인 문제로 안내하지 않는다 | 화면 HTML을 고정한 테스트 | — |
| AC14 | 성적 공개 기간 밖이라 결과가 비면 없다고 답하고, 다른 학기 값을 내놓지 않는다 | 빈 응답을 고정한 테스트 + 대화 | S6-1 |
| AC15 | 학생기본정보 응답의 은행과 계좌번호(`SUD010_BANK_NM`, `SUD010_BANK_CSH`)가 DS 계약, 출력 DTO, AI용 JSON 어디에도 없다 | 두 필드가 든 응답을 고정한 테스트 | — |

★ 실제 학교 계정과 서버가 있어야 확인할 수 있다.

## 5. User Flow (UF-10)

이 기능의 [Design Process ①](../03_design_process.md)에서 그린다. 그릴 갈래: 성적·학적 조회(학생지원시스템 로그인됨 / 안 됨 / 만료), 출결 조회(학생지원시스템 로그인됨 / 안 됨 / 만료, 스마트출결 참고 있음 / 없음 / 실패), 거절 갈래(학사 쓰기, 다른 학생).

## 6. 미확인 항목

- ~~학생지원시스템 조회 허용 목록과 서비스별 학번 매개변수 레지스트리~~ **기록함(2026-11-12)**. 성적·졸업시뮬레이션·학생기본정보·과목출결조회 여섯 화면의 허용 목록, 학번 매개변수(`USER_ID`), 응답 필드가 [07 §5](../layers/data_access/07_student_portal.md#5-조회-허용-목록과-응답-필드-2026-11-12-실측)에 있다. AC10의 허용 목록은 이 표다
- 출력 DTO에 담을 필드. 응답 필드의 뜻은 이름과 화면 머리글로 짐작한 것이라, 구현 때 값과 대조해 고른다. 중간성적·확정전 성적의 목록과 과목출결 내역은 이번에 응답을 보지 못했다(기간 밖, 0행)
- 과목출결조회의 집계 `ATTEND_01`~`ATTEND_04`가 각각 출석·지각·결석 중 무엇인지. F4의 과목별 집계에 쓰려면 알아야 한다
- ~~학생기본정보의 `SELECT_STD_INFO_CHG`를 허용 목록에 넣을지~~ **정함(2026-11-12)**. 허용 목록에 넣고, 은행과 계좌번호 두 필드만 Source에서 버린다(F3, AC15). 주소·전화·보호자 정보 같은 나머지 필드를 어디까지 출력 DTO에 담을지는 구현 때 정한다
- 학생지원시스템 데이터의 원문 링크. 화면 주소(`loadPage.do?jspPage=…`)는 브라우저에 학생지원시스템 로그인이 없으면 열리지 않는다. 로그인 화면(`indexSSO2.do`)을 줄지, 링크를 빼고 화면 이름만 줄지 정한다
- 스마트출결 원문 링크로 과목의 스마트출결 도구 화면을 주는 것(F5, 추론)
- 스마트출결 쿼리의 `user_name`에 넣을 값. [04 §1](../layers/data_access/04_smart_attendance.md#1-접근-경로)은 "로그인 세션의 값"이라고만 쓴다. FS-03이 저장하는 학생 이름(Canvas 내 프로필)과 같은지 확인한다
- 과목마다 스마트출결 세션을 따로 열어야 하는지
- 스마트출결 세션의 유효 시간과 갱신 방법([04 미확인](../layers/data_access/04_smart_attendance.md#미확인-항목))
- 학적·성적용 Repository의 이름. [application §4.1](../layers/02_application.md#41-데이터-repository--gateway)의 예에는 `AttendanceRepository`만 있다. Functional Spec 확정 때 함께 정한다
- 조회 결과를 캐시할지와, 캐시한다면 조회 시각을 무엇으로 줄지. 지금은 캐시가 정의되지 않았으므로 조회 시각은 학교 서버에서 받은 시각이다
- 출력에 학번을 넣어 AI에 줄지. 본인 학번이지만 AI 답에 필요하지 않다
