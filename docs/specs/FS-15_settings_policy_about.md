## 2. 기능 요구사항

### F1 설정 모달

- 사이드바 유틸리티 줄의 설정 버튼으로 연다([UX Strategy §7.1](../06_ux_strategy.md#71-내비게이션-골격)). 연결 알약과 대화 안 연결 안내의 버튼은 설정 > 연결의 해당 행으로 바로 연다(FS-06).
- 모양은 T3 Code의 설정 모달(왼쪽 내비게이션 그룹, 오른쪽 내용, `SettingsRow`)을 그대로 쓰고 항목만 [UX Strategy §7.5](../06_ux_strategy.md#75-설정)의 표로 채운다. 그룹과 항목은 그 표가 원본이다.

| 그룹 | 항목 | 동작을 정하는 곳 |
|---|---|---|
| 일반 | 화면(테마) | 이 문서 F2 |
| | 학과 | FS-05 |
| 연결 | 학교 계정 | [FS-03](FS-03_school_account.md), FS-06 |
| | 학생지원시스템 | FS-04, FS-06 |
| | AI | FS-02, FS-06 |
| 정보 | 정책 | 이 문서 F3 |
| | 앱 정보 | 이 문서 F4 |

- 설정 모달 왼쪽 아래 계정 자리에는 학생 이름을 보인다([UX Strategy §7.1](../06_ux_strategy.md#71-내비게이션-골격)). 값은 `GetAuthState`의 이름이다([FS-03 F7](FS-03_school_account.md)). 이름이 없을 때의 표시는 §6.
- 닫기·키보드 동작(Esc, 바깥 클릭)은 T3 Code의 모달을 따른다.

### F2 테마

- 선택지는 시스템(기본)·라이트·다크 셋이다.
- 시스템이면 OS 설정(`prefers-color-scheme`)을 따르고, 앱이 켜진 동안 OS 설정이 바뀌면 바로 따라간다(추론, §6).
- 적용은 루트 요소의 `.dark` 클래스로 한다([presentation §2.2](../layers/03_presentation.md#22-디자인-토큰)).
- 저장은 WebView `localStorage`에 하고, 읽고 쓰는 일은 `stores/`의 테마 store 하나만 한다. 코어 설정(`SettingsRepository`)에 두지 않으므로 `cdx`와 AI는 테마를 모른다([application §4.4](../layers/02_application.md#44-사용자-상호작용과-로컬-저장)).
- 고르면 바로 적용되고, 앱을 다시 시작해도 남는다. 저장값이 없거나 읽을 수 없거나 셋 중 하나가 아니면 시스템으로 다룬다(추론, §6).
- 앱이 처음 그려질 때 저장한 테마와 다른 테마가 잠깐 보이지 않게 한다(추론, §6).

### F3 정책

- 정책 화면은 `GetPolicy`가 돌려주는 원문을 그대로 보인다. 원문은 `usecases/ai` crate에 포함한 Markdown 파일 하나이고, `cdx policy`도 같은 원문을 돌려준다([application §3](../layers/02_application.md#3-유스케이스-후보), [entrypoints §4](../layers/04_entrypoints.md#4-cdx-명령)). 화면이 원문을 고치거나 줄이지 않는다.
- 원문에는 적어도 다음이 들어 있어야 한다(S10-1, S10-2).

| 내용 | 근거 |
|---|---|
| 비밀(비밀번호·쿠키·토큰)의 저장 위치: OS 키체인(Data Protection 키체인, 앱 접근 그룹) | [security §3](../cross_cutting/01_security.md#3-지킬-것과-강제하는-곳) |
| AI가 보는 범위: 조회 결과만, 비밀은 보지 못한다. `Peer` 원문 대신 요약을 본다 | [security §3](../cross_cutting/01_security.md#3-지킬-것과-강제하는-곳), [§4](../cross_cutting/01_security.md#4-프롬프트-주입-대응-r3) |
| 하지 않는 일: 제출, 출결·진도, 신청, 강의평가, 다른 학생 데이터 조회, OTP 우회 | [PRD §9.1](../01_prd.md#91-비목표-non-goals) |
| 확인 뒤 하는 일: 개인 캘린더 일정, 플래너 메모·완료 표시(FS-11) | [PRD §9.1](../01_prd.md#91-비목표-non-goals), [application §4.4](../layers/02_application.md#44-사용자-상호작용과-로컬-저장) |
| 학교 데이터는 학생 PC에서만 다루고 제3자 서버에 모으지 않는다 | [PRD §9.2](../01_prd.md#92-제약과-위험) |

- 정책은 앱의 말이다. AI 메시지와 겉모습부터 구별되는 설정 화면 안에만 있다(P2).
- 정책 화면은 학교 계정·AI 연결 상태와 관계없이 열린다. 원문이 앱 안에 있으므로 네트워크도 필요 없다(추론, §6).
- AI가 정책 질문을 받으면 `cdx policy`로 조회해 답한다. 이 안내 한 줄은 `ToolGuide`에 있다([entrypoints §6](../layers/04_entrypoints.md#6-toolguide)). 앱이 하지 않는 일을 요청받으면 거절하고 정책으로 이유를 말한다(R4, [UX Strategy §9](../06_ux_strategy.md#9-ai-응답-경험-원칙)).

### F4 앱 정보

- 앱 버전을 보인다. 값은 빌드에 들어간 앱 버전이다(추론, §6).
- 오픈소스 라이선스 목록을 보인다. 목록에는 T3 Code에서 가져온 코드(MIT, 저작권 문구 포함)와 서드파티 패키지(npm, Rust crate, 예: lucide ISC)가 들어간다. 목록은 빌드 때 생성하고, 배포물에도 라이선스 전문을 함께 넣는다([platform §1](../cross_cutting/02_platform.md#1-기술-스택), [UX Strategy §3](../06_ux_strategy.md#3-기준-디자인-t3-code)).
- 앱 정보 화면에 T3 Code의 이름·워드마크·앱 아이콘을 앱 표시로 쓰지 않는다. 라이선스 고지 안의 저작권 문구는 예외다.

## 3. 예외

| 상황 | 판정 | application 오류 | 다음 행동(P5) |
|---|---|---|---|
| 테마 저장값을 읽거나 쓸 수 없음(`localStorage` 실패) | — | 없음(코어를 거치지 않음) | 시스템 테마로 그린다. 학생에게 따로 알리지 않는다(추론) |
| 코어가 꺼져 있을 때 AI가 `cdx policy`를 부름 | — | 없음 | `cdx`가 "앱을 실행하세요" 오류를 낸다([entrypoints §2](../layers/04_entrypoints.md#2-흐름)) |
| 정책 원문 파일이 빌드에 없음 | — | 없음 | 빌드가 실패해야 한다(추론, AC7) |

- `GetPolicy`는 앱 안의 원문만 읽으므로 학교·AI 쪽 application 오류(`NeedsLogin`, `AiUnavailable` 등)가 나지 않는다.

## 5. User Flow (UF-15)

이 기능의 [Design Process ①](../03_design_process.md)에서 그린다. 그릴 갈래: 설정 열기(유틸리티 줄, 연결 알약)와 그룹 이동, 테마 바꾸기(저장 실패 시 시스템으로), 정책 보기, AI에게 정책 묻기(`cdx policy`, 앱이 꺼져 있을 때), 앱 정보·라이선스 보기.

## 6. 미확인 항목

- **로그아웃 뒤 학생 이름 표시**: [UX Strategy §7.1](../06_ux_strategy.md#71-내비게이션-골격)은 계정 자리에 대해 "연결 상태와 관계없이 이름을 보인다"고 쓰고, [FS-03 F6](FS-03_school_account.md)은 "저장한 학생 이름도 지운다"고 쓴다. 로그아웃 뒤에는 이름이 없으므로 계정 자리에 무엇을 보일지(빈 자리, 연결 안내) 정한다. "연결 상태와 관계없이"가 세션 만료·곧 만료를 뜻하는지 로그아웃까지 뜻하는지 UX Strategy에서 확인한다
- **학습 부품의 라이선스 고지**: [platform §1](../cross_cutting/02_platform.md#1-기술-스택)은 고지 대상을 "가져온 코드와 서드파티 패키지(npm, Rust crate)"로 적는다. 설치 과정에서 받는 ffmpeg(LGPL 정적 빌드), 전사 모델(`ggml-large-v3-turbo-q5_0`), VAD 모델(Silero), whisper.cpp는 npm·Rust 패키지가 아니다([learning_adapters §4](../layers/06_learning_adapters.md#4-부품)). LGPL 사이드카는 고지와 소스 제공 방법이 필요할 수 있으므로 고지 목록에 넣을지 정한다. 한글 글꼴의 라이선스([Design Process](../03_design_process.md) Foundation)도 같다
- 오픈소스 라이선스 목록 생성 도구와 형식([platform §4](../cross_cutting/02_platform.md#4-미확인-항목)). AC11은 도구를 정한 뒤 확인한다
- 앱 버전의 원천(Tauri 설정의 버전, `Cargo.toml`)과 빌드 번호·커밋을 함께 보일지(F4, 추론)
- 정책 원문(Markdown)을 화면에 그리는 방법. 앱 원문이라 학교 HTML 정화([presentation §2.3](../layers/03_presentation.md#23-신뢰하지-않는-html과-webview-보안)) 대상은 아니지만, Markdown을 HTML로 바꾸는 위치(Presenter 또는 View)와 CSP 안에서 그리는 방법을 정한다
- 정책 원문에 학습 자료 폴더 위치와 "받은 파일·학습 결과물은 AI에게 요청해 지운다"(S10-3)를 넣을지. 폴더 위치 자체가 아직 없다([FS-12 §6](FS-12_material_download.md#6-미확인-항목))
- 정책 원문을 화면 언어(한국어)로만 둘지. R5(학생이 쓴 언어로 답한다)에 따라 AI는 원문을 번역해 답할 수 있으므로, AC9의 "같은 내용"은 문장 일치가 아니라 내용 일치로 본다
- 시스템 테마일 때 OS 설정 변경을 바로 따라가는지, 첫 화면에서 다른 테마가 잠깐 보이지 않게 하는 방법(F2, 추론). T3 Code의 처리 방식을 확인한다
- 설정 모달의 키보드 단축키(예: macOS `⌘,`). T3 Code와 [UX Strategy §7.5](../06_ux_strategy.md#75-설정)에 근거가 있는지 확인하고, 없으면 두지 않는다
