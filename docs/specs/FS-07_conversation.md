## 1. 범위

## 2. 기능 요구사항

### F1 대화 시작

- 사이드바의 "새 대화"나 `/clear`(F6)로 새 대화를 만든다. 새 대화는 대화 목록 맨 위에 생긴다.
- AI 프로세스는 **대화마다 하나**를 띄워 그 대화 동안 계속 쓴다. 키체인 허용 창을 줄이기 위해서다([ai_adapters §3](../layers/05_ai_adapters.md#3-실행-모드)). 시작 구간은 FS-02 F7에 따라 한 번에 하나씩 돈다.
- `AiSession.start(session_spec)`의 실행 모드는 **대화**다. 사용자의 설정·스킬·플러그인·MCP·커맨드를 그대로 쓴다(S7). `ToolGuide`, 모델, 재개할 세션 ID를 함께 넘긴다.
- 프로세스를 띄울 때 코어는 대화 단위 IPC 토큰을 만들어 넘기고, 대화가 끝나면 폐기한다([entrypoints §3](../layers/04_entrypoints.md#3-ipc)). 이 대화에서 나온 `cdx` 요청, 확인 요청, 작업은 이 대화 ID를 가진다.
- 시작 전에 AI를 쓸 수 있는지 확인한다. 쓸 수 없으면 대화를 시작하지 않고 `AiUnavailable`의 사유에 맞는 앱 메시지를 남긴다(FS-02 F6). 메시지에는 AI 연결 행으로 가는 버튼이 있다([UX Strategy §7.5](../06_ux_strategy.md#75-설정)).
- 빈 대화에는 T3 Code 빈 화면 구조에 자리가 있으면 시나리오에서 뽑은 예시 질문을 둔다([UX Strategy §7.2](../06_ux_strategy.md#72-mvp-화면)).

### F2 전송

- composer에 쓴 글을 `send`로 보낸다. 보낸 글은 바로 학생 메시지로 보이고 기록에 저장된다.
- 응답은 중립 이벤트로 받는다([application §4.2](../layers/02_application.md#42-ai)). `TextDelta`는 AI 메시지에 이어 붙이고, `ToolUse`·`ToolResult`는 AI 메시지 안에 도구 사용으로 보이며, `Done`이면 응답을 끝낸다.
- 응답하는 동안 그 대화의 상태는 "Working"(경과 시간 표시)이다. 다른 대화로 옮겨 가 질문할 수 있고, 각 대화는 따로 응답한다(P6).
- 응답 중에 같은 대화에 다시 보낼 수 있는지는 정하지 않았다(§6). 그때까지는 응답 중 전송 버튼 자리를 취소 버튼으로 바꾼다(추론).
- 대화 안의 링크는 OS 브라우저로 연다([presentation §2.3](../layers/03_presentation.md#23-신뢰하지-않는-html과-webview-보안)).

### F3 취소

- 응답 중에 취소 버튼(또는 단축키)을 누르면 `cancel`로 지금 응답만 멈춘다. 대화와 프로세스는 남고, 다음 메시지를 바로 보낼 수 있다.
- 이미 받은 응답 조각은 남기고, 취소됐다는 앱 메시지를 붙인다(추론, §6).
- 취소 뒤 그 대화의 상태는 Working에서 벗어난다. 실패로 보이지 않는다.
- 취소하면 그 응답이 일으킨 열린 요청을 모두 정리한다. 응답이 멈추면 그 요청의 결과를 받을 곳이 없기 때문이다.
  - 쓰기 확인 창([FS-11](FS-11_personal_schedule_write.md)): 거부로 처리하고 창을 닫는다. 쓰기는 실행되지 않는다(`Rejected(UserDeclined)`).
  - 권한 확인 창(F7): 거부로 돌려주고 창을 닫는다.
  - OTP 창([FS-03 F5](FS-03_school_account.md#f5-끊긴-연결-이어-가기))과 학생지원시스템 로그인 창([FS-04](FS-04_student_portal_login.md)): 이 대화의 요청은 끝내고 다시 실행하지 않는다. 창이 다른 대화의 요청도 기다리고 있으면 창은 남고, 이 대화만 창의 대상에서 빠진다.
  - 대기 상한을 넘겨 요청이 이미 `NeedsLogin`으로 끝난 뒤 남아 있는 OTP 창([FS-03 F5](FS-03_school_account.md#f5-끊긴-연결-이어-가기))은 이 대화의 요청을 기다리지 않으므로 취소와 관계없이 남는다.
  - 이 대화에서 이미 시작한 오래 걸리는 작업([FS-13](FS-13_slide_pdf_and_script_jobs.md))은 응답 취소로 멈추지 않는다. 작업은 작업 카드의 취소로만 멈춘다(S7-1·S7-2, 추론).

### F4 앱 메시지와 AI 메시지 (P2)

| 종류 | 누가 만드나 | 예 |
|---|---|---|
| 학생 메시지 | 학생 | 질문, 슬래시 커맨드 |
| AI 메시지 | AI 제공자의 응답(중립 이벤트) | 답변, 도구 사용 |
| 앱 메시지 | 코어(유스케이스 결과·오류를 Presenter가 바꾼 것) | 연결 안내, 오류와 다음 행동, 지원하지 않는 커맨드 안내, 취소 알림, 재로그인 뒤 안내([FS-03 F5](FS-03_school_account.md#f5-끊긴-연결-이어-가기)), `Peer` 시점 경고 표시 |

- 앱 메시지는 AI 메시지와 **겉모습부터** 다르게 그린다(아이콘, 배경, 위치 중 무엇으로 구별할지는 Design Process ②·③).
- 앱 메시지 모양은 코어가 만든 값으로만 그린다. AI가 쓴 글(Markdown, HTML, 특정 문구)은 어떤 내용이어도 AI 메시지 모양으로 그린다. AI 글이 앱 메시지나 확인 창처럼 보이게 하는 경로가 없다.
- 앱 메시지는 대화 기록에 함께 저장되고, 대화를 다시 열면 같은 자리에 보인다(추론, §6).
- 앱 메시지의 행동 버튼(연결 행 열기, 다시 시도 등)은 하나다(P5).

### F5 대화 목록과 재개 (S9-3)

- 사이드바는 `ConversationRepository`의 대화를 최근 순으로 보인다. 행마다 제목과 대화별 상태(F8)를 보인다.
- 대화를 고르면 앱 기록에서 이전 내용(학생·AI·앱 메시지)을 그린다. **대화 기록의 원본은 앱이다**([presentation §3](../layers/03_presentation.md#3-대화-화면의-슬래시-커맨드)).
- 다시 연 대화에 메시지를 보내면 저장해 둔 제공자 세션 ID를 `session_spec`의 재개 값으로 넘겨 프로세스를 띄운다. 앱을 다시 시작한 뒤에도 맥락이 이어진 답이 나온다(S9-3).
- 제공자가 재개를 지원하는지는 `capabilities()`로 안다. 재개할 수 없으면(지원 안 함, 제공자 기록이 없어짐 등) 새 제공자 세션으로 시작하고, 이전 맥락이 AI에게 이어지지 않는다는 앱 메시지를 남긴다(추론, §6).
- 앱이 닫히면 모든 대화 프로세스가 끝난다([System Architecture §2](../02_system_architecture.md#2-프로세스-구조)). 응답 도중이었으면 다음에 열 때 그 응답은 받은 데까지만 보인다(추론).
- `/resume` 선택기는 쓰지 않는다(F6). 지난 대화는 사이드바에서만 고른다.

### F6 슬래시 커맨드 (S9-1, S9-2)

- composer에서 `/`를 입력하면 자동 완성에 커맨드와 스킬이 보인다. 목록은 대화 시작 이벤트(`system/init`의 `slash_commands`·`skills`)에서 받는다([ai_adapters §4](../layers/05_ai_adapters.md#4-슬래시-커맨드-전달)).
- 커맨드의 분류는 `AiSession.capabilities()`로 받는다. 분류 기준은 [presentation §3](../layers/03_presentation.md#3-대화-화면의-슬래시-커맨드)이다.

| 분류 | 예 | 앱 동작 |
|---|---|---|
| 앱이 대신 처리 | `/clear`, `/login`, `/model` | `/clear`: 새 대화(F1). `/login`: AI 연결 행(FS-02 F3). `/model`: 모델 선택기를 열고 고른 값을 `session_spec`의 모델로 쓴다. CLI에 보내지 않는다 |
| 그대로 전달 | `/compact`, 사용자 커스텀 커맨드, 스킬·플러그인 커맨드 | 학생이 쓴 그대로 사용자 메시지로 CLI에 보낸다. 결과는 AI 메시지로 보인다 |
| 지원하지 않음 | `/config`, `/mcp` 화면, `/resume` 선택기 | CLI에 보내지 않고, 지원하지 않는다는 것과 대신 할 일을 앱 메시지로 보인다(P4, W5) |

- 지원하지 않는 커맨드의 "대신 할 일" 예: `/config`는 터미널의 Claude Code에서 설정한다, `/resume`는 사이드바에서 대화를 고른다. 정확한 문구는 Foundation이다.
- 자동 완성에서도 지원하지 않는 커맨드는 구별해 보이거나 빼고, 앱 처리 커맨드는 앱 동작 설명을 보인다(추론, Design Process ②).

### F7 권한 확인 (`PermissionRequest`)

- 대화 모드에서 미리 허용한 것은 `cdx`뿐이다. 그 밖의 도구가 권한이 필요하면 CLI가 앱에 요청을 넘기고(`--permission-prompts host`), 코어는 중립 이벤트 `PermissionRequest`로 받는다([ai_adapters §3](../layers/05_ai_adapters.md#3-실행-모드)).
- 앱은 **권한 확인 창**(C1)을 띄운다. 창에는 요청한 도구와 실행할 내용(예: 명령 원문)을 CLI가 넘긴 값 그대로 보인다. AI가 대화에서 한 설명은 창에 넣지 않는다.
- 학생이 허용하거나 거부하면 `respond_permission`으로 돌려준다. 거부하면 그 도구는 실행되지 않고, AI는 거부를 받아 응답을 이어 간다.
- 창이 떠 있는 동안 그 대화의 상태는 "Approval"이다(FS-06, [UX Strategy §7.4](../06_ux_strategy.md#74-대화별-상태)). 학생은 다른 대화를 쓸 수 있다.
- 한 대화에서 여러 요청이 오면 한 번에 창 하나만 보이고 차례로 묻는다(추론).
- 응답을 취소(F3)하면 그 대화의 열린 권한 요청은 거부로 돌려주고 창을 닫는다(추론, §6).
- 사용자가 자기 설정에서 넓게 허용해 둔 도구는 CLI가 묻지 않으므로 창이 뜨지 않는다. 이는 [security §6](../cross_cutting/01_security.md#6-수용한-위험)의 수용한 위험이다.

### F8 대화별 상태

- 이 기능은 대화마다 다음 값을 코어에 알린다. 상태 하나를 우선순위로 골라 사이드바에 보이는 판정은 FS-06이 한다([presentation §1](../layers/03_presentation.md#1-개요) `presenters/shell`).

| 값 | 생기는 때 | 사라지는 때 |
|---|---|---|
| 권한 확인 대기 | `PermissionRequest`를 받음 | 학생이 응답하거나 응답을 취소함(F3) |
| AI 응답 중 | 전송 | `Done`, `Error`, 취소 |
| 사용 한도 | `UsageLimit` | 다음 전송이 성공함(추론) |
| 응답 실패 | `Error`, 프로세스가 예기치 않게 끝남 | 다음 전송이 성공함(추론) |
| 보지 않은 완료 | 학생이 그 대화를 보고 있지 않을 때 `Done` | 학생이 그 대화를 엶 |

- 같은 대화의 OTP 입력 대기(FS-03), 쓰기 확인 대기(FS-11), 작업 진행(FS-13)도 같은 대화 ID로 FS-06에 들어간다.

### F9 AI에게 파일 삭제를 맡기기 (S10-3)

- "다운로드 받은 동영상 모두 지워 줘" 같은 요청은 AI가 자기 도구(예: Bash 삭제 명령)로 처리한다. `cdx`에는 삭제 명령이 없고, 앱은 따로 삭제 기능을 두지 않는다.
- 삭제 명령은 미리 허용한 `cdx`가 아니므로 F7의 권한 확인 창을 거친다. 학생이 허용해야 지워지고, 거부하면 아무것도 지워지지 않는다.
- 앱 내부 데이터(대화 기록, 설정, HMAC 기록)를 AI가 지워 생기는 결과는 MVP에서 앱이 책임지지 않는다. 키체인 항목은 AI가 지울 수 없다([UX Strategy §4](../06_ux_strategy.md#a10-앱의-데이터보안-정책이-궁금한-사람)).

## 3. 예외

| 상황 | 판정 | application 오류 | 다음 행동(P5) |

## 5. User Flow (UF-07)

이 기능의 [Design Process ①](../03_design_process.md)에서 그린다. 그릴 갈래: 새 대화 → 전송 → 응답(F1·F2, AI를 쓸 수 없을 때 포함), 취소(F3), 지난 대화 재개(F5, 재개 실패 포함), 슬래시 커맨드 세 분류(F6), 권한 확인 허용·거부(F7), 파일 삭제 요청(F9).

## 6. 미확인 항목

- **"Limited"가 풀리는 조건**: F8 표와 AC18은 다음 전송이 성공하면 "Limited"가 사라진다고 본다(추론). 한도가 풀리는 시각이 지나면 전송 없이도 풀어야 하는지, CLI가 한도 해제를 따로 알려 주는지([ai_adapters §8](../layers/05_ai_adapters.md#8-미확인-항목))를 확인한다
- **AI 응답 실패에 대응하는 application 오류가 없다.** 중립 이벤트 `Error`와 프로세스 비정상 종료가 어느 application 오류로 바뀌는지 [application §4.5](../layers/02_application.md#45-application-오류)에 없다(`AiUnavailable`의 사유도 아니고 `Temporary`는 "네트워크·요청 제한"이다). 아키텍처에 없음 → UX Strategy §12 후보
- **대화 제목을 어떻게 만드는지가 아키텍처에 없다.** 사이드바 행에 제목이 필요하다(T3 Code 구조). 첫 메시지를 자를지, AI에게 맡길지 정한다. 아키텍처에 없음 → UX Strategy §12 후보
- **"보지 않은 완료"의 기록 위치.** [presentation §1](../layers/03_presentation.md#1-개요)은 대화별 상태의 입력으로 "보지 않은 완료"를 들지만, 학생이 대화를 봤는지를 어디에 두는지(메모리만인지, `ConversationRepository`인지) 정해지지 않았다. 앱을 다시 시작해도 남겨야 하는지 정한다
- 권한 확인 요청의 stream-json 메시지 형식과, 학생이 오래 응답하지 않을 때 CLI가 기다리는 시간([ai_adapters §8](../layers/05_ai_adapters.md#8-미확인-항목)). F7의 "취소하면 거부로 돌려준다"(추론)는 이 형식을 본 뒤 정한다
- `/compact`를 stream-json 입력으로 보냈을 때의 동작([ai_adapters §8](../layers/05_ai_adapters.md#8-미확인-항목)). S9-1 AC7의 `/compact`는 이것을 확인한 뒤 점검한다
- `/clear`를 앱 처리로 정한 근거는 "빈 결과가 왔고 문맥이 지워졌는지는 확인하지 않았다"이다([ai_adapters §6](../layers/05_ai_adapters.md)). 앱 처리라 영향은 없다
- **분류 표에 없는 커맨드의 기본 분류.** [presentation §3](../layers/03_presentation.md#3-대화-화면의-슬래시-커맨드)은 예만 들고, `system/init`의 내장 커맨드(측정에서 대화 모드 141개, [ai_adapters §6](../layers/05_ai_adapters.md))를 모두 분류하지 않았다. 표에 없는 내장 커맨드를 "그대로 전달"로 둘지 "지원 안 함"으로 둘지 정한다
- 자동 완성 목록은 대화 시작 이벤트에서 받으므로, 프로세스를 띄우기 전(새 대화의 첫 메시지 전)에는 목록이 없다. 마지막으로 받은 목록을 보일지, 첫 메시지 전에 프로세스를 띄울지 정한다. 띄우면 키체인 읽기가 늘 수 있다(FS-02 F7)
- `/model`로 모델을 바꿀 때 떠 있는 프로세스를 어떻게 다루는지. `--model`은 실행 옵션이므로 프로세스를 다시 띄우고 재개해야 할 수 있다(추론). 다시 띄우면 시작 구간을 다시 거친다
- 응답 중 같은 대화에 다시 보내기(대기열)를 허용할지(F2)
- 취소 때 받은 응답 조각을 남길지와 취소 알림 앱 메시지(F3, 추론)
- 앱 메시지를 대화 기록에 저장하는지(F4, 추론). `ConversationRepository`는 "앱 대화 기록(제공자 세션 ID 색인 포함)"이라고만 한다
- 재개할 수 없을 때(F5) 이전 대화 내용을 새 세션에 넣어 줄지, 맥락 없이 시작할지. 이 문서는 맥락 없이 시작하고 알리는 것으로 썼다(추론)
- 대화 모드의 작업 폴더(`session_spec`의 작업 폴더)를 어디로 할지. AI 도구가 기본으로 보는 폴더이고, F9에서 AI가 다운로드 폴더를 찾는 방법과 이어진다. AI가 다운로드·학습 자료 폴더 위치를 아는 경로(`ToolGuide`, `cdx` 출력 등)도 정해지지 않았다
- AI 메시지 Markdown을 그릴 때의 정화 규칙. [presentation §2.3](../layers/03_presentation.md#23-신뢰하지-않는-html과-webview-보안)은 학교 HTML만 다룬다. AI 응답에도 `Peer` 요약이나 사용자 MCP 결과가 섞일 수 있으므로 같은 규칙을 쓸지 정한다
