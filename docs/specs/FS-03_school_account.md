## 1. 범위

| 하는 것 | 하지 않는 것 |
|---|---|
| 학번·비밀번호·OTP로 처음 연결하기 | OTP 등록을 앱 안에서 대신하기([01_auth §2.1](../layers/data_access/01_auth.md#21-로그인-수단과-otp-미등록-계정)) |
| OTP 없이 세션을 갱신해 연결 유지하기 | 학교 서버의 로그인 유지 범위를 넘어 세션을 늘리기(OTP 우회, [PRD §9.1](../01_prd.md#91-비목표-non-goals)) |
| 세션이 끊겼을 때 OTP 한 번으로 하던 요청 이어 가기 | 공인인증서 로그인 |
| 쿠키 만료 예고와 미리 갱신하기 | AI나 `cdx`가 로그인하기(`cdx`에는 로그인 명령이 없다, [entrypoints §4](../layers/04_entrypoints.md#4-cdx-명령)) |
| 로그아웃(서버 세션 무효화와 로컬 비밀 삭제) | 학생지원시스템 로그인(FS-04) |
| 로그인 때 학생 이름을 받아 저장하기 | 학번을 외부 입력으로 받아 다른 요청에 쓰기([PRD §9.2](../01_prd.md#92-제약과-위험)) |

## 2. 기능 요구사항

### F1 처음 연결

- **입력**: 학번, 비밀번호(앱 화면에서만 받는다), 이어서 OTP 6자리.
- **동작**: 1차 로그인 응답을 [01_auth §2.1](../layers/data_access/01_auth.md#21-로그인-수단과-otp-미등록-계정)의 판정표로 나누고, 판정마다 다음 단계로 간다.

| 판정 | 앱 동작 |
|---|---|
| `OtpRequired` | OTP 입력 칸을 보인다. 입력을 받으면 같은 시도 안에서 나머지 단계를 끝낸다 |
| `OtpNotRegistered` | 미등록 안내와 "브라우저에서 OTP 등록" 버튼을 보인다. 버튼은 학교 매뉴얼을 OS 브라우저로 연다. 입력한 학번은 남기고 비밀번호는 지운다 |
| `NoSecondFactor` | OTP 단계를 건너뛰고 연결을 끝낸다(존재 여부 미확인, 대비만) |
| `PasswordRejected` | 학번·비밀번호를 확인하라는 안내. 학번은 남기고 비밀번호 칸만 비운다 |
| `SourceChanged` | 비밀번호가 틀렸다고 말하지 않는다. 학교 로그인 화면이 바뀌어 지금 연결할 수 없다는 안내 |

- 공인인증서만 쓰는 학생: 1차 로그인 화면에 들어가기 전에 "OTP 인증만 지원한다"는 조건과 OTP 등록 안내를 보인다(P4, S1-6). 매뉴얼상 OTP가 필수 2차 인증이므로, 이 학생이 학번·비밀번호로 로그인하면 `OtpNotRegistered`로 판정될 것으로 본다(추론, §6).
- **출력**: 성공하면 연결됨 상태와 학생 이름(Canvas 내 프로필)을 저장하고 `GetAuthState`가 돌려준다. 학번, 비밀번호, 쿠키, 토큰은 키체인에만 둔다([data_access §2.5](../layers/data_access/README.md) `SessionStore`).

### F2 OTP 입력

- 6자리 숫자만 받는다. 붙여 넣기를 허용하고, 6자리가 되면 바로 제출한다.
- 틀리면 남은 시도 횟수(`fail_count`, `retry_limit`)를 보이고 칸을 비운다.
- 잠기면(403) 풀리기까지 남은 시간(`remaining_seconds`)을 보이고, 그동안 제출할 수 없다.
- 입력한 OTP는 저장하지 않는다.

### F3 연결 유지 (자동 갱신)

- [01_auth §3](../layers/data_access/01_auth.md#3-세션-갱신-otp-없이)의 갱신 시점(사용 중 토큰 만료 5분 전, 유휴 24시간, 앱 시작·잠자기에서 깨어날 때)에 OTP 없이 갱신한다. 학생에게는 아무것도 보이지 않는다.
- 갱신은 코어 안에서 한 번에 하나만 돈다. 바뀐 쿠키는 다른 일보다 먼저 저장한다.
- 로그아웃 상태에서는 어떤 자동 동작도 세션을 되살리지 않는다.

### F4 만료 예고와 미리 갱신

- 로그인 유지 쿠키가 2일 안에 만료되면 연결 행이 "곧 만료"(만료 예정 시각, 갱신 버튼)가 되고 연결 알약에 개수가 오른다(S2-2).
- 갱신 버튼은 F5와 같은 OTP 입력을 받는다. 성공하면 "곧 만료"가 사라진다.

### F5 끊긴 연결 이어 가기

- 대화 중 학교 데이터 요청이 세션 만료를 만나면, **그 요청을 처리하던 유스케이스가** `OtpPrompt`로 OTP 입력 창을 띄우고 답을 기다린다([application §2](../layers/02_application.md#2-원칙): 사용자와 주고받는 흐름은 유스케이스가 조율한다). 창은 요청을 일으킨 대화 ID를 가지며, 그 대화의 상태는 "Input"이 된다([UX Strategy §7.4](../06_ux_strategy.md#74-대화별-상태)).
- OTP를 받아 로그인에 성공하면 같은 유스케이스가 **원래 요청을 다시 실행해** 결과를 돌려준다. `cdx` 요청은 그동안 열려 있다가 결과를 받으므로, 같은 대화에 답이 이어진다(P6, S2-1). 학생이 질문을 다시 보낼 필요가 없다. `cdx`와 AI는 다시 시도하지 않는다.
- 기다리는 시간에는 상한을 둔다. 상한은 AI 제공자의 도구 호출 제한 시간보다 짧게 잡는다(§6). 상한을 넘기면 요청은 `NeedsLogin`으로 끝나고, OTP 창은 열린 채 남는다. 그 뒤 로그인에 성공하면 대화에 "로그인됐어요. 다시 물어봐 주세요" 같은 앱 메시지를 남긴다(문구는 Foundation).
- 창을 닫으면 원래 요청은 `NeedsLogin`으로 끝나고, 대화에는 연결 행으로 가는 버튼이 있는 앱 메시지가 남는다.
- 같은 세션 만료로 여러 요청이 동시에 막히면 OTP 창은 하나만 뜬다. 성공하면 막혀 있던 요청을 모두 다시 실행한다.
- 세션을 되살리려면 학번·비밀번호가 키체인에 있어야 한다. 없으면 F1부터 다시 한다.

### F6 로그아웃

- 설정 > 연결 > 학교 계정의 로그아웃 버튼 → 확인 창 → 승인하면 서버 로그아웃([01_auth §4](../layers/data_access/01_auth.md#4-로그아웃))을 시도하고, 결과와 관계없이 로컬의 학번·비밀번호·쿠키·토큰을 지운다.
- 서버 로그아웃이 실패해도(네트워크 등) 로컬은 지우고 로그아웃 상태가 된다. 서버 쪽 `xn_api_token`이 최대 2시간 남는 것은 [01_auth 위험](../layers/data_access/01_auth.md#위험)의 남는 위험이다.
- 로그아웃 뒤 학교 데이터 질문에는 연결 안내가 나온다(S10-3).
- 학과 설정과 대화 기록은 남는다. 저장한 학생 이름을 지울지는 정하지 않았다([FS-15](FS-15_settings_policy_about.md) §6: UX Strategy §7.1의 "연결 상태와 관계없이 이름을 보인다"와 함께 정한다).

### F7 연결 상태 조회

- `GetAuthState`는 상태(로그아웃, 연결됨, 곧 만료, 확인 중), 쿠키 만료 예정 시각, 학생 이름을 돌려준다. 연결 행·알약·온보딩 카드의 표시는 FS-06이 이 값으로 판정한다.
- 키체인 읽기 실패 중 `Locked`, `Misconfigured`는 로그아웃으로 다루지 않는다([data_access §2.5](../layers/data_access/README.md)). `Locked`는 "확인 중"으로 두고 잠시 뒤 다시 읽는다.

## 3. 예외

| 상황 | 판정 | application 오류 | 다음 행동(P5) |
|---|---|---|---|
| 비밀번호가 틀림 | `PasswordRejected` | `Rejected(PasswordIncorrect)` | 학번·비밀번호 확인 |
| OTP 미등록 | `OtpNotRegistered` | `Rejected(OtpNotRegistered)` | 브라우저에서 OTP 등록 |
| OTP가 틀림 | 401 | `Rejected(OtpIncorrect)` | 다시 입력(남은 횟수 표시) |
| OTP 잠김 | 403 | `Rejected(OtpLocked)` | 풀리는 시각까지 대기 |
| 학교 로그인 화면이 바뀜 | `SourceChanged` | `SourceChanged` | 앱 업데이트가 필요하다는 안내 |
| 네트워크 오류·요청 제한 | — | `Temporary` | 다시 시도 |
| 세션 만료(사용 중) | `SessionExpired` | 없음. 유스케이스가 창 안에서 처리하고, 창을 닫거나 대기 상한을 넘기면 `NeedsLogin` | OTP 입력 창(F5) |
| OTP 창을 닫음·대기 상한을 넘김 | — | `NeedsLogin` | 연결 행으로 가는 버튼이 있는 앱 메시지(F5) |
| 갱신 실패(자동) | `SessionExpired` | 없음. 상태만 "로그인 필요"로 바뀐다 | 다음 학교 데이터 요청 때 F5. 그 전까지 연결 행은 "로그인 필요" |
| 키체인 잠김 | `Locked` | — | 학생에게 보이지 않음. 잠시 뒤 재시도 |
| 키체인 설정 오류 | `Misconfigured` | — | 로그아웃으로 다루지 않음. 앱 설치 문제 안내(문구는 Foundation) |

- 화면은 `Rejected`의 사유([application §4.5](../layers/02_application.md#45-application-오류))만 보고 안내를 고른다.

## 4. 수용 기준

| # | 기준 | 확인 방법 | 시나리오 |
|---|---|---|---|
| AC1 | OTP를 등록한 계정은 학번·비밀번호·OTP를 한 번씩 입력하면 연결됨 상태가 되고, 설정 행에 학생 이름이 보인다 | 실제 계정으로 온보딩 학교 단계를 끝낸다 | S1-4 ★ |

| AC5 | 비밀번호가 틀리면 학번은 남고 비밀번호 칸만 비며, 학번·비밀번호 확인 안내가 나온다 | 틀린 비밀번호로 로그인한다 | — ★ |
| AC6 | OTP가 틀리면 남은 횟수가, 잠기면 풀리는 시각이 보이고 잠긴 동안 제출되지 않는다 | 응답을 고정한 테스트(401·403) | — |
| AC7 | 1차 로그인 응답이 판정표 어디에도 맞지 않으면 "비밀번호가 틀렸다"가 아니라 학교 화면이 바뀌었다는 안내가 나온다 | 응답을 고정한 테스트 | — |
| AC8 | 대화 중 세션이 만료되면 OTP 창이 뜨고, 사이드바의 그 대화가 "Input"이 되며, OTP 입력 뒤 원래 질문의 답이 같은 대화에 이어진다. 질문을 다시 보내지 않는다 | 쿠키를 지워 만료를 재현한 뒤 질문한다 ★ | S2-1 |
| AC9 | 세션 만료로 요청 두 개가 동시에 막혀도 OTP 창은 하나만 뜨고, 입력 뒤 두 요청 모두 답이 나온다 | 테스트(메모리 `AuthGateway`) | S2-1 |
| AC10 | 쿠키 만료가 2일 안이면 연결 알약과 학교 계정 행에 만료 예정 시각과 갱신 버튼이 보이고, 갱신 뒤 사라진다 | 만료 시각을 고정한 테스트 + 실제 갱신 ★ | S2-2 |

| AC12 | 서버 로그아웃이 실패해도 로컬 비밀은 지워지고 로그아웃 상태가 된다 | 네트워크를 끊고 로그아웃한다 | S10-3 |
| AC13 | 로그아웃 상태에서는 앱을 다시 시작하거나 잠자기에서 깨어나도 세션이 되살아나지 않는다 | 로그아웃 뒤 재시작·잠자기 | — |
| AC14 | 키체인이 잠겨 읽기에 실패해도(화면 잠금 중) 로그아웃 상태로 바뀌지 않는다 | `SecretStore`가 `Locked`를 내는 테스트 | — |
| AC15 | 비밀번호·OTP·쿠키·토큰이 로그, `cdx` 출력, 대화 기록, 앱 데이터 파일 어디에도 남지 않는다 | 로그인·갱신·로그아웃 뒤 해당 위치에서 값 검색 | — |
| AC16 | 키체인 읽기가 `Misconfigured`로 실패하면 로그아웃 상태로 바뀌지 않고, 연결 행에 앱 설치 문제 안내가 보인다 | `SecretStore`가 `Misconfigured`를 내는 테스트 | — |

## 5. User Flow (UF-03)

이 기능의 [Design Process ①](../03_design_process.md)에서 그린다. 그릴 갈래: 처음 연결(F1·F2의 판정별), 끊긴 연결 이어 가기(F5), 미리 갱신(F4), 로그아웃(F6).

## 6. 미확인 항목

- OTP 미등록 계정과 2차 인증 없는 계정의 1차 로그인 응답 HTML([01_auth 미확인](../layers/data_access/01_auth.md#미확인)). AC3의 실제 계정 확인은 이것을 기록한 뒤 한다
- AI 제공자의 도구 호출 제한 시간(Claude Code의 Bash 기본값)과, 그 값을 `ToolGuide`나 실행 옵션으로 늘릴 수 있는지. F5의 대기 상한을 이 값보다 짧게 정한다
- S1-6의 점검 방법은 "2차 인증 수단 없음으로 판정되면"이라고 쓰지만, [01_auth §2.1](../layers/data_access/01_auth.md#21-로그인-수단과-otp-미등록-계정) 판정표에는 그런 판정이 없다. 공인인증서만 쓰는 학생의 1차 로그인 응답이 `OtpNotRegistered`와 같은지 기록해 확인하고, 다르면 판정을 더하거나 S1-6의 점검 방법을 고친다
- 키체인 `Misconfigured`일 때의 안내 문구와 행동(설치 문제로 볼지)
- OTP 미등록 안내에서 여는 학교 매뉴얼 주소를 앱에 고정할지
