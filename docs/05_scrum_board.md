# CanvasDongseo — 스크럼 보드

| 항목 | 내용 |
|---|---|
| 독자 | 개발자 본인, 후속 문서·구현을 돕는 AI 에이전트 |
| 근거 | [PRD §7.4](01_prd.md#74-개발-방식) |

> **이 문서의 역할**: GitHub Projects 스크럼 보드의 운영 규칙, 필드, View, 템플릿을 정한다. 기능 하나를 화면까지 만드는 단계는 [Design Process](03_design_process.md)가 맡는다.

---

## 1. 운영 규칙

| 항목 | 규칙 |
|---|---|
| 스프린트 | 1주, 월요일에 시작해 일요일에 끝난다. 이름은 `S01`, `S02`, … |
| 백로그 올리기 | 정해진 때가 없다. 생각나면 바로 올린다 |
| 스프린트에 넣기 | 진행 중인 스프린트에도 언제든 넣는다 |
| 정해진 절차 | 1인 개발이라 회고·회의·피드백 같은 필수 절차를 두지 않는다 |
| 템플릿 | 백로그, 스프린트 두 가지만 둔다(§4) |

**쓰는 말**: 한국어로, 쉬운 단어로 쓴다. 팀마다 뜻과 쓰는 법이 달라 헷갈리는 말(에픽, Increment, Story Point 등)은 쓰지 않는다. 큰 일은 백로그 항목을 여러 개로 나누고, 크기는 따로 매기지 않는다.

## 2. 필드

| 필드 | 종류 | 값 |
|---|---|---|
| 상태 | Single select | `미할당`, `진행 중`, `완료` |
| 스프린트 | Iteration | 1주, 월요일 시작. 반복 이름을 `S01`~`S05`로 바꾼다 |

## 3. View

| View | 모양 | 필터 | 묶는 기준 |
|---|---|---|---|
| 전체 백로그 | Table | 없음 | 스프린트로 묶기(Group by): `S01`~`S05`, 스프린트 미할당 — 6개 그룹, 그룹마다 접고 펼 수 있다 |
| 현재 스프린트 | Board | `스프린트:@current` | 열: 상태(`미할당`, `진행 중`, `완료`) |
| 다음 스프린트 | Board | `스프린트:@next` | 열: 상태 |
| 지난 스프린트 | Board | `스프린트:@previous` | 열: 상태 |

- 스프린트가 비어 있는 항목의 그룹 이름은 GitHub가 정한다(필드 이름을 붙인 "No 스프린트" 형태). 이 그룹이 "스프린트 미할당"이다.
- `S06` 이후의 반복을 더하면 전체 백로그에 그룹이 늘어난다.

## 4. 템플릿

이슈 템플릿은 [`.github/ISSUE_TEMPLATE/`](../.github/ISSUE_TEMPLATE/)에 있다.

| 템플릿 | 파일 | 쓰는 때 | 칸 |
|---|---|---|---|
| 백로그 | `backlog.yml` | 할 일 하나 | 할 일, 왜 필요한지, 끝났다고 보는 기준, 관련 Actor·시나리오(선택), 화면 작업 단계(선택, [Design Process](03_design_process.md) ①~⑥) |
| 스프린트 | `sprint.yml` | 스프린트 하나 | 스프린트 이름, 기간, 이번 스프린트에 끝내고 싶은 것, 메모(선택) |

## 5. 처음 설정하는 순서

이 레포에는 Project를 만들고 View를 구성하는 도구가 없어서 직접 설정한다.

1. 레포의 **Projects** 탭에서 새 Project를 만든다(시작 템플릿 없이 Table).
2. 기본 필드 **Status**를 `상태`로 이름을 바꾸고, 값을 `미할당`, `진행 중`, `완료`로 바꾼다.
3. **Iteration** 필드를 `스프린트`라는 이름으로 더한다. 기간 1주, 시작일은 월요일로 하고, 반복 다섯 개의 이름을 `S01`~`S05`로 바꾼다.
4. §3의 View 네 개를 만든다. 필터 입력이 받아들여지지 않으면 필드 이름을 확인한다.
5. Project의 **Workflows**에서 다음을 켠다.
   - Auto-add to project: 이 레포의 새 이슈를 자동으로 넣는다
   - Item added to project: 상태를 `미할당`으로
   - Item closed: 상태를 `완료`로
